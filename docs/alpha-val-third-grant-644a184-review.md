## Contract conflict requiring Main decision

The revised `2ed9f17` contract proposed owner/ancestor integrity checks, accepted final modes `0600`/`0644`, and ACL-unknown denial. The implementation deliberately **omits all three** after a single macOS legacy-mode probe found that the old path loader accepted `0600`, `0644`, `0640`, `0444`, `0400`, `0666` and `0622`. Existing readable-mode behavior is preserved, but a world-writable grant file or writable ancestor can supply a new publisher trust root before the final open. No-follow and one-descriptor reading close the check/read race; they do not authenticate grant-file custody. The source owner documented the change, but it is a material divergence from the previously reviewed proposed filesystem boundary and requires an explicit Main contract decision before intake. At minimum, state whether Alpha accepts all legacy readable modes under an operator-custody assumption, or adopts a versioned stricter file profile with migration and Linux/macOS tests. The frozen release must not treat a permissive file as independently authenticated publisher authority. Ancestor symlink rejection also tightens compatibility, and only macOS `/var`/`/tmp` aliases are handled; Linux/Debian/Ubuntu behavior remains untested here.

The implementation constructs `Path` components before validation. `Path` normalizes a literal `.` component, so the stated rejection of every `.` component is not directly enforced by `parts`; parent `..` remains visible and is rejected. This is not evidence of a grant bypass by itself, but the path-input contract and its test need alignment. The new test file does not cover every G/F row in the proposal (notably ancestor permissions/ACL and complete F08 platform behavior). The default CLI must still report independent Evidence status as unknown; local signed-event authenticity cannot promote status or authorize enforcement.
