# Phase 4F-R revision: agent-owned denial before broker lease claim

**Proposal only; no implementation authorization.** Baseline `d15a3a756b8066c5cb2d98665662220e52f4a7d6`; predecessor proposal `ea448932ed17a2c55ac02adf259a9396879dac2a`; VAL-R clarification `6c7589e87bcb000f4df0cbe3959d56edea3ea3b3`. VAL-R correctly rejects the target sentinel's proxy `AgentDenialReceipt.v1` as evidence that an agent received and committed a withdrawal. That record is removed from the *agent-denial* closure path. The sentinel remains a separate, target-owned restrictive hold with its own measured target denominator. The inherited five-second gate remains **FAILED** and distributed enforcement disabled.

## Conditional mechanism that preserves the frozen metric

The **restarted agent process itself** enters a narrowly confined `unclaimed_deny_only` phase before even connecting to NATS or trying to reclaim the retained broker KV lease. It loads its operator-enrolled local configuration and canonical audit SQLite, then reads the independently pinned T4/T5 withdrawal authorities directly, without coordinator or JetStream delivery. For every exact scoped withdrawal that passes the current native acceptance rule, the agent checks the signed issuer/grant, exact finding and Evidence mapping, its own local inventory and local policy, proof freshness and revocation precedence. It then commits the ordinary `revocation_decisions` row and exact `revoked_targets` tombstone in **that pre-enrolled agent's existing durable SQLite database**, with a proof provenance row in the same transaction. A separate independent read-only connection must observe the row. This is a local **deny-only audit capability**, not a broker identity claim, local plan approval, target mutation, ACK, cursor advance or positive enforcement authority.

The agent's stable UUID, canonical audit path and agent-to-target mapping are operator-enrolled before the fault. The restarted process must reopen the *same* canonical audit database; a sidecar's own database, target store, coordinator journal, witness receipt or copied agent UUID does not qualify. If two local processes open that database, SQLite serializes a unique `(withdrawal event ID, event digest, target finding digest)` decision; identical replay returns the same logical denial, and conflicting bytes fail closed. A completed transaction must atomically include the denial, tombstone and exact proof provenance. The current `core.evaluate_revocation()` checks Mesh signature/scope but does **not** bind native T4/T5 or local inventory; the current `storage.record_revocation()` has no proof provenance or concurrent duplicate CAS. Both require reviewed interface changes before this proposal can be implemented. The existing `recovery.advance_journal()` remains fenced and separate.

The no-broker-lease phase may **only** appraise independently witnessed withdrawals and commit restrictive agent-owned audit state. It cannot subscribe/fetch from JetStream, process ordinary findings, emit allow decisions, update a replay cursor, confirm an ACK, issue target commands, consume a positive local approval, clear a tombstone or reopen a route. Once a current owner generation and broker lease are established, ordinary signed-journal reconciliation sees the same decision and advances a generation-bound cursor only after verifying the durable row; ACK follows. A stalled KV claim therefore remains fail-closed for positive authority while the earlier agent-owned denial can meet a bounded reporting deadline if independent Trust and the canonical audit store stay reachable.

## Exact acceptance and local policy

Proposed input `VerifiedAgentWithdrawal.v1` includes canonical signed withdrawal/event digest; pinned issuer key/grant and target-publisher scope; finding UUID/digest; exact Evidence bundle/claim digest; T4 witness admission receipt and covered checkpoint/consistency pin; all four authenticated current withdrawal views with an explicit witnessed floor; both current T5 status operators and exact scope/contradiction result; challenge nonce; audience/deployment UUID; earliest proof/key/status expiry. The record is a **local appraisal result**, not a remotely transmitted execution command. One validly scoped issuer signature plus a durable pinned-witness receipt can establish a withdrawal obligation only when the current all-four view rule and T5 exact status confirm it. A forged or out-of-scope issuer cannot produce a specific tombstone, even if one witness signs a receipt. Missing, stale, conflicting or withdrawn proof yields `unknown/conflict`, blocks new positive authority and may cause only a separate locally authorized uncertainty hold. Recheck freshness after the last network I/O and immediately before SQLite commit. A cached positive status or receipt cannot extend expiry.

Proposed local decision context `AgentDenialEvaluation.v1` binds deployment/agent UUID, authenticated source key/grant, exact withdrawal and finding/Evidence digests, `VerifiedAgentWithdrawal.v1` digest, inventory identity/version match, local denial policy ID/version, canonical audit store identity and current monotonic deadline. The agent must record the same structured reason and exact scope that the existing dry-run decision schema expects. It may record an exact negative decision only under a locally enrolled policy for that agent and target; an untrusted coordinator cannot add issuers, targets or policy rules. A different agent's row or target sentinel receipt never counts. The target sentinel may independently commit a restrictive hold under its separately approved exact-plan safety capability, but that state is reported as target protection, not as agent delivery.

## Owner fencing, stale sessions and recovery order

The earlier `OwnerEpochAnchor.v1`, `TargetDenialCommit.v1`, `DeliveryEpoch.v1` and `WriterBarrier.v1` remain **unadopted** positive-transfer proposals. The deny-only audit path does not claim a new target-owner generation. It cannot be used as proof that the old broker session is fenced. The target checks current target-home generation, fence, exact plan, local approval, native T4/T5 cut and earliest deadline inside every positive protected transaction; its independent safety sentinel holds protected routes when authority is unknown. A paused old agent may resume with a valid old signature and KV revision. It can at most attempt an idempotent exact negative audit; it cannot gain new positive authority or advance the successor's cursor through this path. A late old ACK may affect retired broker transport metadata but cannot certify a denial or move the generation-bound authoritative cursor. If all-writer fencing and an independent rollback-resistant owner anchor are unavailable, the successor remains denied positive authority until the old lease naturally expires; the proposed early audit does **not** change that wait.

The crash order is `process restart → reopen canonical agent SQLite → direct T4/T5 discovery → signature/grant + inventory + policy check → atomic agent-owned negative audit → independent read-only observation → later ordinary KV claim → generation-bound replay cursor → broker ACK`. If the process dies before audit commit, no denial exists and the timer keeps running. If it dies after commit but before cursor or ACK, a replacement rechecks exact proof and treats the row as idempotent, then advances progress only when current ownership is proven. A coordinator-suppressed Mesh event cannot suppress direct witness discovery; if witness views cannot be obtained, the agent cannot fabricate a specific withdrawal denial. A restored agent SQLite snapshot missing a previously committed tombstone blocks new positive decisions until independent T4/T5 and an external monotonic audit/owner anchor reconcile it. Restoring target and witness stores together beyond their last external anchor is outside the proved fault model and remains NO-GO.

**Four-witness outage:** the proposed withdrawal profile requires all four fresh authenticated views to establish a current positive appraisal and complete withdrawal view. If one view is unavailable, a 3-of-4 sealed history cut can still be checked, but that alone cannot establish the exact current withdrawal-specific status. Each affected agent may record a separate `unknown_status_hold`, and the target sentinel may preserve its restrictive hold, but neither is a `revocation_decisions` accepted-withdrawal row. The pair is missed or censored and the five-second release gate cannot pass. A single withheld but valid receipt, fabricated receipt, stale view, conflicting checkpoint or revoked issuer key must be distinguished in raw results; a valid signature alone never settles correctness.

## Bound and impossibility conditions

This design can meet the deadline **only conditionally**: the replacement agent process starts, its canonical audit database is writable, and the required independent T4/T5 proof plus inventory/policy checks complete before both mandatory five-second deadlines. The broker may be down throughout; the direct witness route must be independent of it. The frozen clocks begin at independently witnessed submission and durable admission, not at process restart or connectivity restoration. No optimization can beat the earliest time at which the agent-owned store and required proof are available. If the fault kills the entire agent deployment with no independently started replacement, isolates its canonical audit store, withholds a required witness view, or partitions all paths to independent Trust for longer than five seconds, an exact `revocation_decisions` commit within five seconds is impossible under this oracle. An on-time target hold does not change that fact. The proposal therefore does **not** claim a universal five-second guarantee across unbounded partitions or all-four-view outages.

The local agent, its inventory/policy files and canonical audit storage are trusted in this conditional argument. A compromised agent with unrestricted write access to its own SQLite can fabricate or erase rows; an independent audit anchor and host integrity controls would be required to extend this result to Byzantine agents. Local container role separation cannot establish that property or independent administrative custody.

Under current code, `agent_runtime.run()` blocks on the 30-second broker KV claim **before** creating a local agent/audit evaluator and both critical lanes. Current `recovery.reconcile()` checks the broker lease before each signed event and advances its cursor separately after the agent decision. There is no direct native T4/T5-to-agent audit adapter or verified Mesh-to-Evidence mapping. Thus the current implementation cannot meet the frozen pre-intake SIGKILL case. The retained 10/10 external miss and independent absent-at-30.559-second poll remain the measured result; the proposed path has **no performance result** and no authority-changing code has been written.

## Independent tests required before an implementation decision

VAL-R's `6c7589e` oracle is controlling: three pre-enrolled agents × two scoped withdrawals × three fresh repeats × four arms = **72 agent-owned fault pairs**, plus **18 healthy control pairs**, with **1,000 ordinary pending findings per fault run**. Each pair requires its own agent's committed `revocation_decisions` row, read through a separate read-only SQLite connection after that agent's own signature, Trust, inventory and local-policy evaluation. Both submission-to-denial and independently witnessed durable-admission-to-denial conservative upper bounds must be ≤5,000 ms. Target sentinel hold and target fence have separate target denominators. Predeclare process kill scope, agent/target roster, evidence digests, local policies, witness availability, owner generation, partition duration and eligible/censored pairs before faults. No post-hoc exclusion or timer reset at restart.

Test the four frozen arms: pre-intake SIGKILL plus broker restart; broker/network partition and rejoin; durable denial then lost ACK and replay; stale owner against successor during delivery. For the new direct-Trust path, kill **the entire agent process** before intake, start a replacement with the same canonical audit store, and show the audit row appears before its retained KV lease can be reclaimed. Kill the replacement during verification, immediately before SQLite commit, after commit/before cursor, and after cursor/before ACK. Test an old process concurrently writing the same audit DB, as well as an old process on a different host with no canonical store access; the latter must be reported unavailable, not silently considered delivered. Run the negative sentinel control from VAL-R: two killed or partitioned agents and three target-owned receipts cannot score 3/3 agent denials.

Inject forged/out-of-scope issuer, wrong Evidence digest, expired grant/proof, one fabricated witness receipt, one authentic but withheld witness receipt, stale/conflicting four-view status, T5 contradiction, one required witness offline, malicious coordinator suppressing Mesh traffic, restored agent audit/target snapshot, old signed target command and delayed old-session ACK. Require zero unauthorized positive writes, zero falsely accepted withdrawal-specific tombstones, no target reopening, one logical denial per valid event, no cursor advance before durable decision, and independently observed target restriction before serving/health traffic. Report missing agent rows and witness samples as misses/censored, not passes. Stage clocks must distinguish direct witness admission, source replay, signature/Trust check, inventory/policy, agent SQLite commit, target fence, KV claim, ACK and cursor. Local `perf_counter_ns` comparisons are valid only on one host; cross-host intervals need independent observations and clock-error bounds.

The target-owned sentinel may improve protection latency, but VAL-R must score it separately. The full 72+18 all-agent test cannot be claimed by a one-agent dry-run trace or a proxy receipt. Local containers cannot prove independent multi-host custody or rollback anchors. Native T4/T5 and existing restrictive recovery remain authoritative; the five-second gate, native 4F release and distributed enforcement remain **NO-GO** until a reviewed candidate passes the frozen oracle without any skipped or censored eligible pair.
