# Phase 5C-1 threat model and frozen-test proposal

**Proposal only at `ec939e14a5acd438ff0d5fa562ed61a70b68f3c9`.** VAL-1 must freeze acceptance independently before reviewing an implementation. All tests below use disposable, authorized localhost/container fixtures. No public scanning, exploit payload, production host, arbitrary shell, remote model or network dependency fetch is in scope. No test here closes the existing 5B alpha, 5A release or 4F distributed-enforcement gates.

## Assets and adversaries

Protect the host and lab target from writes, privilege escalation, process escape, network exfiltration and unintended traffic; protect private inventory and advisory material from logs; protect a reviewer from false `safe`/`verified` interpretations. Untrusted inputs include advisory text, model suggestions, profile IDs, local fixture bytes, filenames, malformed JSON, worker output and a coordinator's event metadata. A compromised diagnostic worker may lie, spin, fork, fill output, attempt to read host paths or launch a second process. A malicious local user may race symlinks or replace a fixture after preflight. A compromised operator enrollment or OS isolation boundary is outside a mere parser proof and must remain a stated residual risk.

| Threat | Required fail-closed control and test |
| --- | --- |
| Advisory/model prompt injection or command smuggling | Treat strings as data. Try shell metacharacters, arguments resembling flags, JSON role spoofing and instruction text in each input field. No shell or dynamic command may be constructed; no probe starts without explicit local operator selection of an installed profile. |
| Unenrolled target or path escape | Reject wrong target ID, expired/changed enrollment, relative traversal, symlink/device/FIFO, mount swap and digest mismatch. Open selected fixture through a pinned root/descriptor and recheck exact bytes before launch. Any race yields rejected/inconclusive, not an observation. |
| Worker code/image substitution | Verify pinned digest before launch; alter one byte, tag, profile version or interpreter path. Reject before observation. A container tag alone is not a pin. |
| Escape, network or subprocess attempt | Worker runs without network, capabilities, host write mount or privilege. Trace attempted connect/bind/exec/privilege/write syscalls. The one reviewed launcher-to-worker exec is expected; any worker-initiated second exec or outbound socket is a failure. A Python audit hook alone does not prove absence. |
| Resource exhaustion and malformed result | Test request/output at, below and above declared limits; infinite loop, fork attempt, output flood, closed stdout, slow reader, timeout and cancellation. Bound CPU, wall, RSS, pids, file size and tmpfs; emit one bounded inconclusive/rejected record and dispose of the worker. |
| False observation or control bypass | Positive and negative control failures, missing target data, conflicting observations, cached/stale source, parser error and partial output cannot become `not-observed` or `observed`. Compare exact fixture and control digests. A valid result is still provisional, never Evidence truth. |
| Audit laundering or replay | Reuse run ID with changed source, alter a transcript hash or replay an old result against a new snapshot. Reject correlation or mark unknown. An unkeyed local digest is not independently witnessed history. |
| Cross-plane authority confusion | Send diagnostic JSON to `SignedFinding`, Evidence and local approval parsers and protected-writer entry points in negative tests. It must be rejected or ignored with zero target mutations, zero broker authority, zero positive approvals and no change to native T4/T5 state. |
| Privacy leakage | Seed fixture with fake credential canaries and hostile control characters; inspect stdout, stderr, logs, temporary files and process arguments. No canary, raw host document, token or environment value may appear. Explicit output path is the only allowed host write. |

## Independent acceptance matrix

VAL-1 should seal exact profiles, fixture bytes, image digest, runner commit and expected labels *before* implementation review. At minimum: one allowed inert marker with passing controls; one absent marker with passing controls; two failed controls; two target-scope mismatches; two source/profile byte mutations; one symlink race; one oversized request and result; one timeout; one worker crash; one closed/slow consumer each; one network, second-exec, privilege and host-write attempt each; one prompt-injection/advisory command string; one replay; and one cross-plane parser rejection for each authority schema. Record planned, attempted, eligible, completed, rejected, inconclusive, skipped and failed counts separately. A missing tracer or unavailable Linux sandbox makes the kernel-side gate **unverified**, never passed.

Every default invocation must leave declared host writable trees byte, mode, ownership, mtime and path identical before/after; supplement with syscall traces for attempted effects. The worker may use only disposable private tmpfs. A declared explicit output-path test may write exactly the requested artifact and no other host path. Read-only host root and unprivileged UID are required in the Linux fixture. A leak, escape, unauthorized write or authority promotion is a safety failure regardless of otherwise passing functional cases.

## Reproducible resource experiment

Use the same pinned image, CPU quota, memory cap, profile, fixture input and warm/cold classification for baseline and candidate. The baseline is a deterministic inert control checker on the same fixture; compare it with the candidate runner to isolate launch, containment and transcript overhead, rather than comparing unrelated advisories. Run **at least 30 fresh processes per arm**, in paired randomized order, plus separate three-repeat failure arms. Report all startup failures and censored runs. Timestamp preflight start, worker launch, first bounded output, parser completion, audit emission and disposal with a same-host monotonic clock; use UTC only for correlation. A cross-host trial needs measured offset/error bounds and conservative end-to-end upper bounds.

Publish p50/p95/p99/max for request-to-result and each stage, CPU user/system, peak child and aggregate RSS, output bytes, tmpfs and host writes, syscall violation attempts, false `observed`/`not-observed`, inconclusive coverage, cleanup time, and costs of rejected inputs. With 30 runs, p99 is close to the maximum and must be described as a descriptive sample, not a service guarantee. Keep raw per-run outcomes, exact denominators, first failed attempts, image/source hashes and measurement scripts. No performance improvement or safety completeness is claimed until VAL-1 repeats the exact pin independently.

## Release criteria

An isolated *local-lab diagnostic preview* could be considered only after the reviewed contract, OS containment and no-write/no-network tests, exact-pin independent adversarial result, full integrated regression and a documented resource envelope pass. Any skipped Linux syscall arm, target-scope ambiguity, observed marker without passing controls, authority promotion or unsafe cleanup is NO-GO for that preview. External diagnostics, production use, autonomous scheduling, evidence-signing and protected writes require separate architecture and authorization; this document grants none of them.
