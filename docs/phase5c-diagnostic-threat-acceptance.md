# Phase 5C-1 threat model and frozen-test proposal

**Revised proposal only at `ec939e14a5acd438ff0d5fa562ed61a70b68f3c9`, after VAL-1 review `20d4e187cda1e0854c60ee830c49af52c81ed389`.** VAL-1's independent freeze `0960e6f43af83b221da47e873cc64a9fe899fca7` controls implementation scoring. All tests use disposable, authorized localhost/container fixtures. No public scanning, exploit payload, production host, arbitrary shell, remote model or network dependency fetch is in scope. No test here closes the existing 5B alpha, 5A release or 4F distributed-enforcement gates.

## Assets and adversaries

Protect the host and lab target from writes, privilege escalation, process escape, network exfiltration and unintended traffic; protect private inventory and advisory material from logs; protect a reviewer from false `safe`/`verified` interpretations. Untrusted inputs include advisory text, model suggestions, profile IDs, local fixture bytes, filenames, malformed JSON, worker output and a coordinator's event metadata. A compromised diagnostic worker may lie, spin, fork, fill output, attempt to read host paths or launch a second process. A malicious local user may race symlinks or replace a fixture after preflight. A compromised operator enrollment or OS isolation boundary is outside a mere parser proof and must remain a stated residual risk.

| Threat | Required fail-closed control and test |
| --- | --- |
| Advisory/model prompt injection or command smuggling | Treat strings as data. Try shell metacharacters, arguments resembling flags, JSON role spoofing and instruction text in each input field. No shell or dynamic command may be constructed; a JSON `operator-invoked=true` is ignored. No probe starts without an out-of-band one-use local operator capability for an installed profile and enrolled fixture. |
| Unenrolled target or path escape | Reject wrong target ID, expired/changed enrollment, relative traversal, symlink/device/FIFO, mount swap and digest mismatch. Open the fixture relative to a preopened root, copy exact bytes into a sealed memory descriptor, rehash after sealing and inside the worker. The worker never reopens a host path. Any race yields rejected/inconclusive, not an observation. |
| Worker code/image substitution | Verify pinned digest before launch; alter one byte, tag, profile version or interpreter path. Reject before observation. A container tag alone is not a pin. |
| Escape, network or subprocess attempt | Worker runs without network, capabilities, host write mount or privilege under a pinned image, namespaces and reviewed second-stage seccomp profile. Independently trace attempted connect/bind/exec/privilege/write syscalls. The one reviewed launcher-to-worker exec is expected; any worker-initiated second exec or outbound socket is a failure, even if blocked. A Python audit hook alone does not prove absence. |
| Resource exhaustion and malformed result | Test request/output at, below and above declared limits; infinite loop, fork attempt, output flood, closed stdout, slow reader, timeout and cancellation. Enforce 3 s wall, 1 s CPU, hard cgroup 256 MiB memory, four PIDs, 32 open worker file descriptors, 1 MiB worker result, 4 KiB sanitized stderr and 8 MiB tmpfs. Aggregate child/cgroup accounting, kill/reap and cleanup readback are required; a lone `RLIMIT_AS` is insufficient. |
| False observation or control bypass | Positive and negative control failures, missing target data, conflicting observations, cached/stale source, parser error and partial output cannot become `not-observed` or `observed`. Compare exact fixture and control digests. A valid result is still provisional, never Evidence truth. |
| Audit laundering or replay | Reuse run ID with changed source, copy a valid JSON request without its out-of-band capability, replay a consumed capability, alter a transcript hash or replay an old result against a new sealed snapshot. Reject correlation or mark unknown. An unkeyed local digest is not independently witnessed history. |
| Cross-plane authority confusion | Send diagnostic JSON to `SignedFinding`, Evidence and local approval parsers and protected-writer entry points in negative tests. It must be rejected or ignored with zero target mutations, zero broker authority, zero positive approvals and no change to native T4/T5 state. |
| Privacy leakage | Seed fixture with fake credential canaries and hostile control characters; inspect stdout, stderr, logs, temporary files and process arguments. No canary, raw host document, capability handle, token or environment value may appear. Only a separately operator-minted, one-use output-directory capability may create the exact granted file; arbitrary request paths are inert. |

## Independent acceptance matrix

The controlling independent safety denominator is **24 logical cases × three fresh repeats = 72 scored trials**, not the performance sample. VAL-1 must seal case IDs, exact input bytes/digests, fixture image/containment/tracer pins and expected restricted outcomes before implementation review. The six frozen strata each contain four cases: (1) benign local controls, (2) hostile input/path/shell/prompt injection, (3) attempted network/host/protected-writer effects, (4) timeout/crash/output flood/concurrency, (5) stale/revoked/contradictory/unknown Trust status, and (6) escape/rollback/symlink/credential exposure. The owner may propose subcases, but cannot substitute them for one of VAL-1's 24 sealed cases. Every repeat uses fresh state. Record planned, attempted, eligible, observed, rejected, inconclusive, failed, skipped and censored separately. A missing tracer or unavailable Linux sandbox makes the kernel-side gate **unverified**, never passed.

Every default invocation must leave declared host writable trees byte, mode, ownership, mtime and path identical before/after; supplement with independent syscall traces for attempted effects. The worker may use only disposable private tmpfs. An explicit output-capability test may create exactly the operator-granted file through a preopened private directory; a JSON output path alone must fail. Read-only host root, non-root UID, network/user/mount/PID namespaces, no capabilities, no new privileges, reviewed second-stage seccomp, hard cgroup memory/PID limits and worker/fixture digests are required in the Linux fixture. A leak, escape, unauthorized *attempted* write/connect/exec/privilege, false `safe`/`verified`, or authority promotion is a safety failure even when a kernel control blocks the attempt. Worker-produced positive/negative controls remain provisional; passing controls do not authenticate an underlying vulnerability claim.

## Reproducible resource experiment

The **separate performance denominator** is at least **30 fresh processes per baseline arm and 30 per candidate arm**, paired in randomized order; it cannot be pooled with the 72 safety trials. Use the same pinned image, CPU quota, hard memory/PID caps, profile, sealed fixture input and warm/cold classification for both arms. The baseline is a deterministic inert control checker on the same fixture; compare it with the candidate runner to isolate launch, containment and transcript overhead, rather than comparing unrelated advisories. Add distinct three-repeat fault arms and report startup failures/censoring. Timestamp preflight start, worker launch, first bounded output, parser completion, audit emission and disposal with one same-host monotonic clock; use UTC only for correlation. A cross-host trial needs measured offset/error bounds and conservative end-to-end upper bounds.

Publish p50/p95/p99/max for request-to-result and each stage, CPU user/system, peak child and aggregate RSS, output bytes, tmpfs and host writes, syscall violation attempts, false `observed`/`not-observed`, inconclusive coverage, cleanup time, and costs of rejected inputs. With 30 runs, p99 is close to the maximum and must be described as a descriptive sample, not a service guarantee. Keep raw per-run outcomes, exact denominators, first failed attempts, image/source/seccomp/tracer hashes and measurement scripts. No performance improvement or safety completeness is claimed until VAL-1 repeats the exact pin independently.

## Release criteria

An isolated *local-lab diagnostic preview* could be considered only after the reviewed contract, **72/72 frozen safety trials satisfy their expected restricted outcomes**, OS containment and no-write/no-network tests with independent attempted-effect tracing, the separate 30/arm resource experiment, exact-pin independent adversarial result, full integrated regression and a documented resource envelope pass. Any skipped Linux syscall arm, target-scope ambiguity, observed marker without passing controls, authority promotion or unsafe cleanup is NO-GO for that preview. The concrete seccomp bytes/digest, tracer binary/digest, immutable input and output-capability implementation, and complete writable-mount inventory are not supplied today; those are implementation and acceptance blockers. External diagnostics, production use, autonomous scheduling, evidence-signing and protected writes require separate architecture and authorization; this document grants none of them.
