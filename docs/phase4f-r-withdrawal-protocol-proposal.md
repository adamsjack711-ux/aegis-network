## Proven problem and separate authorities

The external one-host dry-run fault arm recorded **10/10 eligible pairs over 5,000 ms**, with 30 busy FILE KV claims and a replacement claim near 30.5 seconds. VAL-D independently read both exact SQLite denials absent 30,559.741 ms after broker restart and present at 30,585.717 ms. An alive broker-restart control was below two seconds. These data locate the delay in the retained broker lease, but they do not justify early lease deletion or prove target protection. A broker KV revision, the native target `ownership.generation`, a T4 checkpoint, a T5 status, an agent audit row and a JetStream ACK/cursor have different authorities and failure domains. No equality or inferred authority between them is allowed.

The proposal has two independent results: **timely restrictive denial** through a target-resident, locally enrolled safety sentinel that never acquires positive authority, and **later positive-owner transfer** through a separately anchored generation and complete writer barrier. The sentinel is not the crashed Mesh agent and must not use its retained broker lease. Whether its per-agent durable record satisfies the frozen metric requires explicit VAL-R review; a generic target hold or broker receipt cannot silently be relabeled an agent withdrawal decision.

## Proposed authority records and trust assumptions

Every proposed record has a new version/domain separation, canonical byte encoding, Ed25519 signature from an enrolled role where specified, immutable UUID/digest identifiers, bounded size and expiry, and strict unknown-version rejection. Existing SignedFinding, Mesh revocation, T4/T5 and local approval signed bytes stay unchanged. The local target home and operator key are trusted for target policy and fencing; T4 uses the existing fixed four-witness roster with at most one faulty witness, and T5 uses its independently enrolled status authorities. The proposed owner anchor is a **new role namespace using established T4 Merkle/consistency primitives**, not a claim that the current T4 journal already stores ownership. If all target and independent anchor domains can be rolled back together, the protocol cannot prove monotonicity and must hold.

## State machine and crash order

**Withdrawal safety lane:** `unseen` → `witnessed_exact` → `locally_appraised` → `target_denial_committed` → `agent_receipt_observed` → `generation_bound_cursor` → `broker_ACK_observed`. The target-resident sentinel queries independently pinned T4/T5 authorities; it does not poll the coordinator for authority or impersonate the crashed Mesh consumer. A coordinator may help transport bytes but its silence cannot suppress direct independent status discovery. `unknown/conflict` branches to `uncertainty_hold` and never creates `AgentDenialReceipt.v1` for a specific withdrawal. The sentinel and incumbent agent may race to report the same verified withdrawal; target and audit unique keys make it one logical denial, and the target transaction fence prevents an in-flight positive commit from passing after the hold. If crash occurs after target denial but before agent receipt, both must be in one transaction or recovery must treat the receipt as missing and fail the all-agent metric. If crash occurs after receipt but before cursor/ACK, replay is idempotent and the denial persists.

**Owner lane:** `active(g)` → `prepared(g+1), all targets held` → `independently anchored(g+1)` → `barrier_complete(g+1)` → `active(g+1)`; any failure goes to `held_unknown`, not back to `active(g)`. The target home is the only generation CAS authority; a separate witness anchor detects home rollback. Prepare is durable before external anchor publication. An anchor without matching target prepare is incomplete. An old target snapshot with generation below the anchor is quarantined before any route or write; a stale checkpoint or equivocation prevents activation. The successor may start a generation-isolated *read-only* reconciliation but cannot advance authoritative cursor or commit a positive target write until the barrier is complete. The old broker lease may expire naturally; it is never shortened or force-deleted to accelerate this lane.

**Stale owner and malicious coordinator:** A paused old owner can resume with a valid signature and old broker session. The target compares its signed command's generation, plan, approval, fence and T4/T5 cut against the current target transaction and rejects it. A late old ACK can only change its retired generation's JetStream consumer metadata; it cannot move the authoritative cursor for `g+1`. A coordinator that withholds an independently accepted withdrawal, reorders Mesh events or replays a positive status cannot affect the sentinel's direct T4/T5 appraisal. If all independent views are unavailable, the target holds under local safety policy, but no specific withdrawal is claimed as confirmed. No remote participant can clear a tombstone or command a reopening.

## Timing, migration and unresolved review decisions

VAL-R must freeze the exact interpretation of an agent's durable denial **before implementation**. The proposed `AgentDenialReceipt.v1` is target-owned and per-enrolled-agent; it is different from today's agent-owned `revocation_decisions` row. A generic hold or a receipt at another agent is not a pass. If VAL-R requires the crashed process itself to write its own SQLite audit, then no sentinel can satisfy the inherited pre-intake SIGKILL gate before the 30-second broker lease expires under this design. Preserve that NO-GO instead of redefining the denominator. The 5,000 ms clock starts at submission as frozen, with witnessed acceptance and restored-connectivity spans reported separately; slow witness admission, missing status, offline agents or partitions are failed/censored explicitly, never subtracted silently.

An owner epoch anchor requires a new T4 namespace/roster credential, durable append-only storage, consistency verification and independent administration. Local Docker containers with separate keys simulate roles but do **not** prove administrative separation or rollback resistance against a shared restored volume. A mixed-version writer that cannot enforce `OwnerEpochAnchor.v1` and `WriterBarrier.v1` stays held. Retain old denial tombstones and maximum generation during migration; no old binary may reopen after upgrade rollback. A safely isolated generation-specific consumer needs a retention/capacity and deletion policy that never discards an unacknowledged signed obligation. A target home or anchor outage is an availability failure, not a reason to accept an older generation.

Open contract decisions for Main/VAL-R: (1) whether `WithdrawalAcceptance.v1` may bind a Mesh revocation to a native Evidence bundle with one exact issuer/scope mapping and how a disagreement is represented; (2) whether the operator-signed plan-bound restrictive safety authorization satisfies the local-approval invariant; (3) whether a target sentinel's per-agent receipt counts as that agent's durable denial; (4) how all four fresh withdrawal views and the 3-of-4 sealed cut interact under one witness outage; (5) what independently administered owner anchor and authenticated workload identity are available in an authorized multi-host lab; and (6) whether generation-isolated JetStream consumers and cursor CAS can be integrated without changing existing signed artifacts. **Until these are decided, no authority-changing implementation is approved.**
