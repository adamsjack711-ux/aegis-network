# Phase 5A-C read-only model evaluation architecture

The approved baseline `3bfd2ab` has an offline deterministic advisory matcher and private `phase5a-research-v2` result. The previous scripted development corpus was 12/12 for both deterministic and scripted provider, with **zero demonstrated model advantage**. A separate independent holdout had 9 correct of 11 mappable cases, two conservative unknown disagreements and one Debian epoch case inconclusive. An unkeyed checksum on a serialized v2 record is not source authentication. [Prior independent review](phase-next-remediation-candidate-review.md).

VAL-D froze the [acceptance oracle](../../phase-next-alpha-astra/docs/phase-next-alpha-validation-freeze.md) at `5c5d94f9c3b9ca99c29301bc743767233599ab4f` before implementation review and owns the new blind labels. This architecture does not authorize an external provider, feed, endpoint, credential or model call.

## Read-only pipeline and frozen interfaces

Local immutable advisory bytes → SHA-256 and acquisition metadata → deterministic normalization into private `Claim` records → exact product/version matching and uncertainty → bounded optional `JSONProvider` research proposal → independent point-by-point source-support check → `ResearchCheck` disposition → read-only report. A generated result can be a hypothesis or a source-supported research point only after exact snapshot bytes, pointer, product, version and asserted effect are checked. It never becomes `SignedFinding`, verifier attestation, current T4/T5 status, local approval or protected-write instruction automatically.

`SignedFinding 1.0`, its Ed25519 canonical bytes, local `InventoryItem(purl, version)` and native T4/T5 stay unchanged. The private v2 record remains informational. If a record crosses a process boundary, the receiver must re-acquire and recheck exact source bytes or have a separately reviewed proof state; a recomputable unkeyed digest and `source_binding` string alone are insufficient. Model prose remains segregated under `raw_hypothesis` and `support=unchecked` unless an independent checker supports each atomic factual assertion. A matching deterministic affected-version result does not validate model impact, exploitability, fix or mitigation prose.

## Experiment design

- Seal the frozen planned **36 independently labeled cases** before model scoring: retain the 12 prior cases and add **24** new blind cases with source bytes, digests, authority/acquisition labels and exact expected outcomes. Balance false positives, conflicting advisories, boundary/prerelease/epoch versions, unsupported citations, prompt injection, ambiguous package identity, withdrawn/stale status and fabricated impact. Mark synthetic role labels as fixtures, not live source authenticity. Record every unmappable case. Until VAL-D seals the 24 new cases, only the original 12 are independently evaluable.
- Run deterministic and provider paths on identical source and asset inputs. Record each attempted and emitted positive point, source entailment for product/version/effect, exact decision, abstention, contradiction, false-positive safety failure, malformed response, timeout and injection obedience. Zero fabricated **supported** claims and zero action/authority promotion are mandatory read-only gates; aggregate accuracy cannot hide a single unsupported point.
- The provider interface must cap input bytes, output tokens, wall time, retries and concurrency; default to an offline fixture and fail closed on malformed or over-budget responses. Do not log private assets or secrets. Any real-model adapter must be separately approved for endpoint, data export, enrollment, licensing, credentials and budget, and run in an isolated laboratory experiment. Without that authorization the real-model arm is **skipped**, not simulated or described as an accuracy result.
- On at least three repeated runs of the locked corpus (when a real model is authorized), distinguish warm/cold startup, measure p50/p95/p99 inference and end-to-end research latency with monotonic clocks, CPU/GPU seconds, peak RSS, input/output tokens and actual provider billing. Compare with deterministic baseline on the same hardware and inputs. A missing billing oracle means USD cost is unmeasured; local compute seconds are reported separately. Repeated scripted fixtures establish harness behavior, not model benefit.

## Acceptance and release boundary

An offline research engineering GO requires the frozen corpus/guardrails, strict private-reader behavior, no network activity and no authority promotion at an exact clean pin. A real-model value claim requires a separately authorized model arm and independent factual scoring. Reusable authenticated Evidence or advisory publication requires source authentication/revalidation and a distinct trust review; no Phase 5A research result may grant local enforcement. Every skipped model, epoch, source-authentication or cost arm remains visible in the handoff.
