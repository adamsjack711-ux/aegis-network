# Phase 4F-B: KV recovery protocol and validation proposal

This proposal is based on clean `feat/phase4f-kv-recovery` at `3bfd2abea430bc8036105ce85adfdc78706d367d`. It precedes VAL-D's new acceptance freeze. No implementation, shared contract, lease setting, or enforcement behavior is changed here. Native T4/T5 and exact local approval remain authoritative; broker state, signatures by themselves, model text and Mesh ACKs cannot grant a protected write. Distributed enforcement remains disabled.

## Measured failure and current boundaries

The retained owner diagnostic at `2fa7321618fc5e7435b339ffa9368de258198d21` has three fresh SIGKILL-before-intake plus broker-restart trials: 30,616.800, 30,604.164 and 30,613.554 ms from submission to first durable dry-run denial. The independent fourth trial is 30,589.201 ms. The original independent pair remains 30,609.654 and 30,709.573 ms. All exceed the inherited 5,000 ms all-agent ceiling. The three instrumented owner runs made 30 busy KV `create()` attempts before a successful claim near 30.5 seconds after restart; critical receipt and audit followed within about 50 ms. A broker-restart-only, agent-alive control took 1,759.519 ms. This localizes the dominant observed delay to waiting for the retained broker FILE KV lease after SIGKILL. It does not prove that an earlier claim is safe. [Raw owner results](phase4f-withdrawal-recovery-results.md) · [Integration review](phase-next-remediation-integration.md).

`src/aegis/identity.py` has a 30-second broker-scoped TTL and a stable UUID claim. `src/aegis/agent_runtime.py` starts critical wire and replay only after claim, then checks the lease before local decision and ACK. `src/aegis/recovery.py` verifies journal continuity but advances its critical cursor after local decision; `src/aegis/storage.py` stores dry-run withdrawal and cursor records. Separately, `src/aegis/ownership.py` maintains a monotonic target-store generation and exact signed command checks inside the target transaction. `src/aegis/mitigation/store.py` rechecks local approval, T4/T5-backed status, generation, fence and earliest deadline at protected commit. These are **distinct** identities and stores: a broker KV revision is not the target generation, a Mesh audit denial is not native T4/T5 status, and a broker ACK/cursor is not a target-side fence. No complete generation-bound ACK/cursor barrier or independently administered multi-host proof is demonstrated by the retained one-host trial.

## Candidate protocol choices, pending contract review

**A. Deny-only observation before ownership transfer.** A local agent or supervisor could receive an independently verified T4/T5 scoped withdrawal or an explicit unknown-status hold while the broker lease is still retained. The only permitted state transition is a durable restriction/quarantine in the enrolled target store, serialized under the same target transaction and monotonic fence used by all protected writers. It must not create a positive decision, consume a local approval, advance an authoritative replay cursor, or ACK a broker message as owner. A withdrawal-specific denial report requires a signed scoped event, current independently witnessed inclusion and Evidence-status denial precedence; an unknown-status hold is reported as a hold, not as acceptance of a particular withdrawal. The current `LocalAgent.evaluate_revocation()` path verifies Mesh publisher trust and writes a dry-run SQLite decision, but it does not provide this native T4/T5 or target transaction binding. Therefore the current code cannot use a preclaim Mesh audit as closure evidence. This choice needs reviewed contracts for T4/T5 proof freshness, issuer scope, conflicting/partial witness views, local target identity, concurrent incumbent, and durable denial report semantics before implementation.

**B. Early successor ownership transfer.** A trusted local operator-controlled supervisor may prove the old process is dead in the disposable single-host fixture, but process death alone does not fence a stale actor across brokers or restored hosts. Before a successor obtains positive write or ACK/cursor authority, the target home must atomically advance its durable generation, every enrolled protected writer must reject the old generation, every relevant ACK/cursor lane must bind the new authenticated session and generation, and a fresh exact local approval plus current T4/T5 cut must be checked at the protected transaction. Lost acknowledgements or incomplete barriers keep positive authority closed. `OwnershipHome.fence()` shows a target-side generation primitive, but no reviewed broker-to-target transfer or all-lane ACK/cursor protocol joins it to the KV lease. Do not decrease TTL, delete the retained KV key, or accept a new KV claim as proof of this barrier. This path is blocked until its cross-component interface and restore behavior are independently reviewed.

Either design must preserve a known safe restriction during outage and recovery, with no silent reopening after lease expiry. If a verified denial-only path and fenced transfer cannot be established, retain the 30-second wait and report the five-second gate as failed. No arbitrary withdrawal issuer can gain denial authority: apply pinned issuer scope and independent T4/T5 acceptance rules, and treat missing/conflicting status as a local quarantine reason rather than as a validated withdrawal.

## Frozen-oracle request to VAL-D

Freeze the exact baseline and original six raw failure traces before implementation, with SHA-256, image IDs, command lines and clean/dirty status. Measure independent witnessed admission, coordinator journal acceptance and submission separately; **submission-to-denial remains the inherited primary five-second comparison**. The existing frozen Phase-next oracle remains a lower bound: three fresh SIGKILL-before-intake plus broker-restart trials; one independent revoker and one mixed publisher-sequence withdrawal; declared enrolled-agent and eligible agent-withdrawal-pair denominators; all eligible pairs independently read as durable denial within **5,000 ms**, with no omitted or silently censored agent. Report isolation intervals for disconnected actors and both submission-to-denial and restored-connectivity-to-denial. A future positive result does not erase the old failures.

For a candidate A, independently read the target store *before* any serving or health request and prove a higher-fence restriction, exact withdrawal reason/status where claimed, and no positive action, ACK or cursor advance before ownership. Inject a forged/unauthorized withdrawal, one-witness acceptance without required status, stale checkpoint, contradictory status, revoked Evidence and a malicious coordinator. No untrusted party may force a false withdrawal-specific denial; uncertainty may trigger only a documented local hold. Race an incumbent positive write against the preclaim restriction and require the target transaction to serialize safely.

For a candidate B, race two agents on two brokers, duplicate the stable UUID, lose ACK after commit, restore a stale cursor and target snapshot, kill before intake, pause/partition the old owner and resume it after successor claim. Require zero old-generation target writes, zero old-session ACK/cursor advances, monotonic target fence, one logical denial, and explicit failure if any enrolled writer cannot acknowledge the new barrier. Test process restart and broker restart separately and together. A current exact local approval and T4/T5 cut must still be checked inside every protected transaction.

Use the retained one-host monotonic `perf_counter_ns` stage instrumentation for local comparisons. For multi-host trials, record local spans plus externally witnessed boundaries and clock-error bounds; never subtract unsynchronized process clocks. Report p50/p95/p99, max and all-agent coverage with repeated fresh states, pending ordinary backlog, CPU/RSS and target hold cost. Report every failure, skip, timeout and missing sample. Independently administered hosts, custody, rollback anchors and production safety remain separate NO-GO gates.

## Ownership and sequencing

This branch owns identity and critical-transport diagnostics (`src/aegis/identity.py`, `src/aegis/agent_runtime.py`, `src/aegis/recovery.py`, `scripts/phase4e_withdrawal_recovery_check.py`) and focused fault tests under `tests/phase4e/`, only after VAL-D freezes its oracle and the integration lead reviews any versioned interface proposal. Native target store, `ownership.py`, T4/T5 status/history and signed finding contracts belong to their existing owners; this branch will not edit them. First secure the validator freeze, then choose A or B by independent proof obligations, implement the smallest reviewed change, run the frozen negatives and three fresh trials, and hand a clean exact commit to integration. Do not merge to master or promote distributed write authority.
