## Independent review findings and unresolved gates

The Phase 4F proposal correctly keeps the original native ownership-loss ordering failure and distinguishes broker acknowledgement from target safety. Its proposed generation token has no approved encoding, storage migration or proof that an old JetStream session cannot advance a successor's server-side cursor. The protected native COMMIT hook and proactive hold ordering need an explicit lock and crash model before implementation.

The Phase 5A proposal separates research from the existing signed Finding and Evidence roles. At review, `src/aegis/intelligence/{__init__,feeds,models}.py` appeared untracked in the 5A worktree, outside its design-only owner commit `086a1df2764bd496a811cff584861bd02570df24`. Read-only inspection found a `FeedClient.fetch` capable of outbound HTTPS to NVD, OSV, CISA KEV and GitHub. Its author, approval path and compatibility with the offline freeze are unknown. Preserve the files and keep them outside acceptance and integration until ownership and interface review establish provenance. No external fetch is authorized in this preparation.

The Phase 5B proposal correctly avoids `LocalAgent.evaluate` and proposes bounded local input. Its source selection, Debian distro namespace and package-version semantics, optional signed finding trust-root format and `pyproject.toml` entry point remain interface decisions. The proposed exit codes and schema need golden vectors before an installability claim.

Distributed autonomous enforcement, shared C writer authority, external host testing, production integrations and any AI-derived protected write remain NO-GO. A clean local run will not close independent custody, rollback anchor or authenticated physical multi-host gates. The current work is architecture and validation preparation. No new performance or security property is claimed as demonstrated.
