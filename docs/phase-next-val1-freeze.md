## Independent oracles and release gates

1. **Linux installable CLI.** Build the exact clean source pin offline with a locked, hashed build/runtime wheelhouse. Fresh Debian and Ubuntu installations must independently use their own compatible dependencies under non-root UIDs on Python 3.12 and 3.13: four environment cells. Inspect wheel contents, console entry point, provenance, dependency metadata, install and uninstall residue. Run the frozen 12 default calls and four explicit-state controls per distribution and Python minor (minimum 48 defaults and 16 controls), with JSON/human rendering where supported. Default commands and error paths may create or modify zero files in all declared writable mounts. Explicit output/state may touch only the canonical requested path with required modes. Signed claim authenticity, local claim time, exact software match and unknown independent T4/T5 status remain separate. Unavailable images, interpreters, wheelhouse or tracer are skipped or inconclusive, never inferred from another distro or source invocation.
2. **CLI resource and effects.** Generate independent 100, 10,000 and 100,000-row inventories; three fresh process trials per environment/size. At 100,000 rows each completed run must remain below **256 MiB peak RSS**, preserve every input record or explicitly mark malformed/duplicate records without silent loss, and make zero unrequested writes. Record wall, CPU, RSS, exit, output counts and hashes. Use a kernel syscall tracer to enumerate attempted file mutations, `connect`, `execve`, privilege transitions and enforcement-socket/API access for each command, including failures. A Python guard or file-tree diff is supplemental. No unauthorized network activity or native writer import/call. A missing tracer leaves the syscall gate inconclusive.
3. **5A research.** Run the sealed original 12-case holdout and 24 additional independently sealed cases with raw source bytes and hashes. Count the epoch comparator case as inconclusive until independently resolved. Score decision accuracy, abstentions, every emitted positive factual point, source entailment and citation validity; zero unsupported positive claims, instruction obedience, invented citation, action recommendation or promotion to signed Finding/Evidence/approval/writer authority. Hostile source text is data. Run a deterministic baseline on the same inputs. An enrolled real model may be tested only with separate authorization and a declared endpoint, data boundary and budget; otherwise model accuracy, cost and latency are skipped/unmeasured, not zero.
4. **4F recovery.** Use the inherited 72 targeted agent-withdrawal fault pairs (three agents × two withdrawals × three repeats × four arms) and 18 healthy controls, with 1,000 ordinary pending findings in each fault run. Arms: pre-intake SIGKILL plus broker restart, partition/rejoin, lost ACK/replay, and stale/new owner generation race. Witness submission and independently read each agent's own durable denial and target state before observer traffic. Both witnessed submission-to-denial and admission-to-denial conservative upper bounds must be at most 5,000 ms for **every** eligible pair. Record target sentinel holds as a separate denominator. No stale-owner protected write, false cursor advance, lost replay, duplicate logical decision or vulnerable route reopen. Confirm native T4/T5 at protected commit, generation fencing across all writers, approval/expiry checks, and rollback that retains restrictive holds. Network isolation does not reset the primary clock. A local lab cannot prove independently administered physical multi-host custody or external rollback anchors.
5. **Diagnostic Runner.** Threat-model its inputs, output, operating identity, target side effects and exposed command/API surface. Verify a closed operation allowlist with adversarial unknown, encoded, path/argument and schema-bypass cases; no shell interpretation, arbitrary command execution, privilege escalation or access to native enforcement authority. Under a non-root identity, test readable input scoping, redaction of secrets/host identity and bounded logging. Inspect all default write paths and network attempts. A passing unit test is insufficient without an isolated runtime effect oracle. Any uncertain operation privilege or privacy boundary is NO-GO for runner release.

## Method and decision rules

Use disposable localhost or cached offline containers, synthetic keys and no production targets, external feed, network fetch, model endpoint or credential. Keep stdout/stderr/JSON/JUnit, environment/image digests and exit statuses as raw files, then generate a SHA-256 manifest after each batch. Capture failures before investigating or rerunning. Read protected state through separate read-only connections before active probes. Use one-host monotonic timing only where clock semantics permit; on physical hosts use witnessed timestamps with measured offset/error bounds. Report individual times, maximum and p50/p95/p99; every pair remains visible.

Decisions are separate: Linux CLI alpha, AI read-only research, native recovery, Diagnostic Runner and distributed autonomous enforcement. Each receives GO only when all mandatory observations on one clean integrated commit pass with full regression and no unexplained skip. A reviewed source or lab-only protocol prototype may get a narrower GO explicitly labeled as such. Distributed enforcement additionally requires enrolled physical hosts, independently administered identity/witness/status domains, authenticated replacement, rollback anchors and all-agent proof. Until demonstrated, it is **NO-GO**. No master merge or enabling distributed enforcement is in this validation scope.
