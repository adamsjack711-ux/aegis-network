**Decision: GO for an isolated deny-only protocol prototype; REVISE the contract before implementation intake; NO-GO for 4F release or distributed enforcement.** The proposal now preserves the agent-owned SQLite denial numerator and keeps target sentinel holds separate. The proposed evidence-map signature uses Ed25519 with domain separation, which is appropriate as a design choice, but its encoding vector has placeholder native material/environment digests and is **not** a valid Evidence proof. Its test seed must remain disposable. No signature vector alone proves source correctness, authority custody, independent intake or denial precedence.

## Required falsification before adoption

1. Test one valid revocation with **all four** fresh complete views and two valid T5 Evidence status operators, separately from a 3-of-4 native positive cut. Then suppress the coordinator event; direct discovery must still find the exact signed target. Test one authentic-but-withheld receipt, one fabricated view, one missing page/terminal, one view offline, conflicting roots, stale challenge, wrong nonce, exhausted 256-record shadow view and 1,000 ordinary queued findings. Exact accepted-row count must stay zero on unsupported proof; positive writes stay blocked.
2. Test a signed, scope-valid Mesh revocation while Evidence remains `reproduced`; T4 should deny the finding, while T5 must not be forced to report an Evidence withdrawal it has not seen. Test separate signed Evidence withdrawal and contradiction. The adapter must never promote `phase4e` shadow `WithdrawalView` or a string reason into native status.
3. Test wrong Finding digest, publisher, sequence, claim/bundle/material/environment digest, target, audience, operator map, inventory/policy/plan snapshot, grant role, expired key and same UUID/different body. Test delayed final Trust read crossing earliest expiry and changed local snapshot before commit. All must have zero accepted specific-denial rows or a separately labeled unknown hold as specified.
4. Test old/new processes on one canonical DB, cloned agent UUID on a different DB, restored agent/target/cursor/anchor, lost ACK, stale old-session signed target command and broker restart. Require one exact logical denial, no cursor advance before durable row, generation-bound cursor/ACK rejection and no target reopening. The deny-only audit path does not itself prove target fencing or safe rollback.
5. Run frozen **72 agent-owned fault pairs + 18 healthy control pairs** with 1,000 ordinary pending findings in every fault run. Read each pre-enrolled agent's own canonical `revocation_decisions` and provenance using a separate read-only connection. Both witnessed submission→agent-owned durable denial and durable admission→same denial conservative upper bounds must be ≤5,000 ms for every eligible pair. A target sentinel record is a separate target-protection denominator. An unavailable agent, canonical store or required witness view remains missed/censored; no timer reset at respawn. Report all skips, tails, CPU/RSS and the original failure alongside the candidate.

No physical multi-host enrolled principals, independently administered witness/anchor custody, authenticated replacement host, or broad rollback test is established by this proposal. It is an actionable protocol design, not measured recovery. Native T4/T5 remains authoritative, and both the five-second all-agent gate and distributed autonomous enforcement remain **NO-GO**.
