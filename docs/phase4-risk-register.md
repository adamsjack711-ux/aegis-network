## Independent baseline review record for P4-01

Reviewed `recovery.py`, `postgres.py`, `phase3c.py` and the existing hardening tests against the pinned baseline. `events_after()` derives a head and page from one coordinator's journal. `reconcile()` checks shape, cursor regression, ranges and signatures. It cannot distinguish “caught up” from a view in which a valid later event was omitted and the advertised head stayed unchanged. Authenticating the connection to the same coordinator would not establish completeness. PostgreSQL sequence positions also need not be contiguous, so a numeric contiguity check is not a completeness proof.

Ran an isolated, in-process matched comparison using `httpx.MockTransport`, fresh Ed25519 publisher/revoker keys, an exact local package match, a valid scoped withdrawal and separate SQLite audits initially at cursor 1. The lease double returned success in both arms. The complete response had head 2 and the signed withdrawal at position 2. `MeshIntake.fresh()` advanced the cursor to 2 and raised `FINDING_REVOKED`. The withheld response had head 1 and no events. The same method returned a freshness deadline with cursor 1. Both ran fresh code paths using the same pinned trust. The test made no mitigation writes. This confirms the status prerequisite can succeed in a stale view. It does not establish compromise of the local authority or a target transition.

Record future findings against exact candidate commits with the test boundary, matched control, original observation, independent reviewer, disposition, and fix/test links. Keep a result open if it depends on trust, topology or time assumptions the experiment does not establish.
