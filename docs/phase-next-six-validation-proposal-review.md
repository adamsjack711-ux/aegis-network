## 5B-1 package boundary

The proposal correctly keeps the existing Hatchling backend, default lab dependency set, namespace and signed/authority source untouched while adding a generated `aegis` console and explicit Pydantic runtime requirement. That is a reviewable **minimal metadata diff**; it avoids silently adopting the separate branches' extras split or shared `config.py` loader move. It expressly admits the wheel still contains non-observer modules and the current CLI transitive `config -> core` import. A generated console does not prove observer-only package purity, import safety, zero writes or absence of protected writer effects.

Before package acceptance, freeze actual **wheel archive bytes**, not an extracted Hatchling `RECORD`, plus every runtime wheel SHA/tag/license/provenance. Build wheel and sdist twice from one exact `git archive` and fixed `SOURCE_DATE_EPOCH`; compare byte-for-byte, metadata, `RECORD`, `entry_points.txt`, direct dependencies and existing lab-default compatibility. An archive-less extracted cache is not an independently reviewed wheelhouse. Specify a disposable writable install prefix/venv inside an otherwise read-only-root, non-root container so install/uninstall is observable without implying writes to the protected root. Use `pip --no-index --find-links` with normal dependency resolution; no `--no-deps`, host site packages, source `PYTHONPATH`, borrowed Debian libraries or network fetch. Invoke the installed script directly and verify uninstall residues. The proposal itself records missing reviewed Linux `cryptography`/`pydantic_core` wheel archives, Ubuntu 3.12 libraries and Ubuntu 3.13 image; those cells are **skipped**, not passes.

The frozen platform denominator is real Debian and Ubuntu × Python 3.12 and 3.13, with at least **84 logical installed-console cases** across four cells (12 defaults + five signed negatives + four explicit-state controls each), plus actual JSON/human variants, two offline builds, install/uninstall, import graph, resource/no-write/syscall gates. A full-lab wheel may be considered only with a verified no-enforcement-import/call path and a candid package-surface risk; it cannot be labeled a pure observer wheel. Alpha remains NO-GO even if the minimal metadata experiment builds locally.

## 5B-2 source and privacy boundary

The proposal properly separates source profiling from 5B-1 packaging, retains byte-equivalent output and the `independent_status=unknown` distinction, and acknowledges the observed serializer wall-time cost. It identifies two concrete race candidates: explicit `--state-dir` check/path use and trust-file `stat()` before `config.load_publishers()` read. Reproduce with disposable files and a fixed original failure oracle before editing. A descriptor-relative private grant reader is acceptable only as a **proposed** adapter after exact old/new grant, role, expiry, revocation, rotation, duplicate and scope vectors; shared loader movement, grant interpretation or private output v3 are not approved by this doc. Pin a clean source commit before any implementation review; the current worktree's untracked owner files are preserved untouched.

The frozen resource denominator is **68 child trials** across four installed platform cells: per cell nine 512 MiB 100/10k/100k trials, three malformed/oversized failures, three 256 MiB 100k controls and one slow plus one closed output. Each 100k standard run needs ≤5 s wall/CPU, ≤256 MiB process RSS, ≤64 MiB JSON and zero OOM; error runs ≤2 s/≤128 MiB. Every default/error path has zero host file changes across declared mounts, and explicit state is confined to the canonical opt-in directory. A cached independent syscall observer must record attempted connect, exec, privilege and writable-file effects; source tree equality and `--network none` cannot substitute. SignedFinding 1.0, exact package matching and native T4/T5 uncertainty remain frozen. The existing Kali/Python 3.14 synthetic-Debian source result is a valid bottleneck diagnostic, not an installed Debian/Ubuntu release result.

## 5A-1 research boundary

The proposal maintains distinct denominators: older V01–V12 **11/12** from a different text parser; current candidate adapter **9/12** with V03/V10 conservative unknown and V11 epoch inconclusive; visible sealed 36 planned/34 evaluable/33 exact/zero false affected; 23 private claims attempted and 15 emitted, **zero independently semantically adjudicated**, zero authenticated real advisories. These are not model advantage. The original 6/7 unsupported-positive and pre-repair claim failures remain test inputs. Preserve private v2 `ResearchResult` and v3 evaluator reader boundaries, exact source-byte/quote/role checks, no fabricated reportable positive points, and no route to SignedFinding/Evidence/approval/writer. A synthetic role string, citation or unkeyed digest cannot authenticate source truth.

The frozen V comparison plans **12 × three repeats × fixed/shuffled order = 72 cases per arm, 144 total**. Any new blind corpus must be independently authored, labeled and hashed before owner/model exposure, with all attempted and abstained cases retained. Each emitted factual point needs source-byte evidence and independent semantic adjudication; conditional accuracy is undefined when zero points are emitted. An external provider branch with a caller-set `authorized` flag is not an enrolled model or cost oracle. Under this cycle's no-external-network/model boundary, do not import, construct, invoke or test it against a live endpoint. Without separate explicit authorization, credential custody, data-export scope, model/prompt/schema pin and hard billable-cost stop, the model arm is **skipped** and accuracy, latency and cost remain unmeasured.
