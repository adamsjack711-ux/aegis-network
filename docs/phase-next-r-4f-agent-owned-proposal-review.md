## Metric compatibility and verdict

The revision correctly removes target-owned `AgentDenialReceipt.v1` from the all-agent numerator. A **restarted agent itself** can in principle commit its existing canonical `revocation_decisions` row plus exact tombstone/proof in its pre-enrolled SQLite before claiming the broker lease. An independent read-only connection can then observe a genuinely agent-owned durable denial. The target sentinel remains a separate protective-state metric. This is **conditionally compatible** with the frozen five-second oracle; it is not demonstrated by current code. Both independently witnessed submission→agent denial and durable admission→agent denial must have conservative upper bounds ≤5,000 ms for each eligible agent/withdrawal pair. Time does not restart at agent respawn, witness availability or broker connectivity.

**Verdict: GO for designing an isolated, deny-only local prototype after field-level owner review; REVISE the cross-component contracts before adopting or integrating its output; NO-GO for the five-second release or distributed enforcement.** No current implementation has been timed or proven. If direct Trust, the canonical audit store or an independently started replacement is unavailable beyond the deadline, no exact agent-owned denial can meet the metric. A target hold may still prevent reopening, but it cannot be counted as an agent decision.

## Contract gaps to resolve before code is accepted

1. **Exact Mesh-to-Evidence mapping.** Existing Mesh revocation identifies a finding artifact and signed-body digest; native Evidence status identifies an Evidence bundle/claim cut. Define a versioned, one-to-one canonical mapping for finding UUID/digest, Evidence digest, issuer grant, withdrawal scope and audience. Reject same UUID/different bytes, unmatched bundles, unknown mapping version and contradictory T5 status. A plausible `VerifiedAgentWithdrawal.v1` object cannot authenticate its own provenance.
2. **Independent direct discovery and completeness.** Specify authenticated direct endpoints/roster for all four pinned withdrawal views, how an agent queries *all* valid withdrawals for its exact enrolled target without a coordinator-provided event ID, nonce and checkpoint continuity/floor, bounded pagination and reply size, independent intake, and an auditable last-seen cut. A coordinator that withholds the Mesh event must not also be able to hide the query key. A negative view is usable only if its completeness and freshness are independently verified. One unreachable required view gives `unknown`, no positive authority and no fabricated specific withdrawal.
3. **Local inventory and policy.** Pin the agent's deployment UUID, canonical audit-store identity, target mapping, complete local inventory snapshot/version, previously protected finding/plan and locally enrolled denial policy ID/version. Recheck after the last blocking Trust read and before SQLite commit. Partial, stale or changed inventory/policy cannot produce an unsupported exact accepted-withdrawal claim; it may justify only a separately labeled local hold. An untrusted coordinator cannot add issuers, targets, policy or agent UUIDs.
4. **Proof provenance and commit.** Store the original signed withdrawal bytes/digest, issuer/grant decision, exact native T4/T5 view/checkpoint/consistency and Evidence mapping digests, nonce/audience, all earliest expiries and policy/inventory identity **in the same durable transaction** as `revocation_decisions` and tombstone. Use an exact idempotency key and conflict-on-different-bytes rule. Do not log secrets or treat a T4 receipt, HTTP response or broker ACK as final status. Pin receipt time after the last I/O and reject a proof that expires before commit. An internally consistent local record still needs an independently protected continuity anchor against restored SQLite snapshots.
5. **Duplicate processes and ownership.** The same local UUID in two processes does not prove one canonical agent store. Test simultaneous old/new processes on the same DB, a cloned UUID with a different DB, an old process with stale proof, and an old broker session sending a late ACK. Only the operator-enrolled canonical store's exact row counts, and its negative path grants no target write, positive approval, authoritative cursor or current-generation ACK. Generation/fence checks for **all protected writers** remain separate and mandatory; a pre-claim denial does not fence the old owner.
6. **Witness outage and impossible cases.** The proposed all-four fresh withdrawal views plus 3-of-4 sealed history cut are deliberately more availability-sensitive than history quorum alone. One required view down, stale, conflicting or withheld can block withdrawal-specific acceptance; `unknown_status_hold` and target restriction are separate outcomes, not `revocation_decisions`. If the entire agent deployment remains dead, its canonical SQLite is inaccessible, or all direct Trust paths are partitioned for >5 seconds, the all-agent deadline is impossible under this oracle. Such pairs are declared misses/censored and keep release NO-GO, never removed after the fact.

## Required independent negative and fault tests

- **Authenticity and mapping:** forged/out-of-scope revoker, revoked or expired key, valid signer/wrong finding or Evidence digest, same UUID with different bytes, unsupported mapping version, invalid T5 verifier and contradictory T5 status. Require zero false accepted-withdrawal rows and zero unauthorized positive writes.
- **Discovery:** suppress Mesh/coordinator publication after an independently witnessed valid intake; query all pinned views directly and prove exact discovery. Withhold one authentic receipt, return a stale/partial page or equivocate checkpoints. Missing completeness yields unknown/hold, never fresh positive status or a false tombstone.
- **Freshness:** expire proof, grant, nonce/audience or local policy during a delayed T4/T5 call; verify the final pre-commit check rejects it. Test all-four-current, one-view-offline and 3-of-4-only history controls separately. A one-view outage does not pass the five-second accepted-withdrawal gate.
- **Local state:** complete exact inventory and prior plan positive control; partial/changed inventory, target removed, changed policy, wrong canonical DB path, copied agent UUID and mismatched deployment negative controls. Read the DB through a separate read-only connection before any serving request.
- **Concurrency/crash:** two processes race on one canonical DB with identical and conflicting withdrawal bytes; kill replacement before verification, before commit, after commit/before cursor, after cursor/before ACK. Require one logical exact denial; no cursor/ACK advance before committed row; no positive authority before generation/barrier proof.
- **Rollback and stale owner:** restore an agent DB snapshot that omits a tombstone, restore target/cursor snapshots, resume old signed commands and ACK after successor transfer. A protected route remains restricted and newer fences/cursors never regress. If the external audit/owner anchor is unavailable, hold and report the continuity gap.
- **Metric separation:** kill two of three agents before intake while a target sentinel writes three proxy receipts. Score zero agent-owned denials for the two absent rows, even if one target hold is confirmed. Report target protection and agent-denial denominators separately.
- **Full workload:** 3 pre-enrolled agents × 2 valid withdrawals × 3 fresh states × 4 fault arms = **72 agent-owned fault pairs**, plus **18 healthy controls**, with **1,000 ordinary pending findings in every fault run**. Include pre-intake SIGKILL/broker restart, partition/rejoin, lost ACK/replay and old/new owner delivery. Count every agent/target, skipped or censored pair, stage p50/p95/p99/max, CPU/RSS, backlog and both five-second clocks. A one-agent or smaller-backlog run is diagnostic only.

Local disposable containers can test the protocol state machine. Physical multi-host workload identity, independently administered witness custody and rollback-resistant anchors remain unobservable without separately enrolled authorized hosts and credentials; distributed autonomous enforcement remains disabled.
