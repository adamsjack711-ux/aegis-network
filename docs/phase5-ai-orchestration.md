# Phase 5 read-only intelligence orchestration

**Integration reference:** `8292e531194216a578c32c912d066f98cdbce9ea`. This document freezes the current authority boundary and assigns private, versioned adapter proposals for the next cycle. It does not adopt a new signed protocol or authorize a network feed or model call.

## Data path and authority

`local pinned advisory bytes → authenticated/declared source snapshot → deterministic parse and deduplication → scheduled research task → deterministic baseline and optional bounded provider hypothesis → independent source-point check → ResearchReview → read-only display`. Every stage records input digest, source identity, parser/reviewer version, run ID, time and explicit unknown or inconclusive state. A URL, hash or model citation alone is neither source authentication nor proof that a claim is true. Withdrawal, correction and expiry invalidate cached research keyed by source digest and source-status cut. Scheduling is local, offline and idempotent until a live feed receives separate review.

`SourceSnapshot`, `Claim`, `Asset`, `ResearchResult` and `ResearchCheck` in `src/aegis/intelligence/` are existing **private v1/v2 runtime records**, not shared Evidence or Mesh contracts. The earlier `AdvisoryInput.v1`, `ResearchCandidate.v1`, `ResearchCheck.v1` and `ResearchReview.v1` names in [Phase 5A architecture](phase5a-architecture.md) are **provisional proposals**; they do not field-map to runtime classes automatically. Scout accepts a supplied `SourceSnapshot` and emits normalized `Claim` tuples from local fixtures. The revised Investigator accepts its own private `AdvisoryInput` with `Asset` and pinned snapshots through the exact offline `ScriptedProvider`; an existing separate `JSONProvider` research experiment does not connect these lanes. A cross-lane adapter needs a versioned field map, old/new readers, content/source hash checks and independent negative tests before adoption.

`InventorySnapshot/v1` and `ExposureObservation/v1` remain provisional observation records for the Linux CLI. Only existing exact `InventoryItem(purl, version)` runtime matching is authoritative. `DiagnosticRequest` and `DiagnosticResult` are separately provisional under [the Runner boundary](phase5c-integration-contracts.md). No implicit conversion exists among research, diagnostic, observation, signed finding, Evidence status and local authorization records.

The only authoritative defensive network finding remains `SignedFinding 1.0` in `src/aegis/artifact.py`; its canonical bytes, grants, expiry and revocation are frozen. A research check can mark a hypothesis consistent with supplied bytes, but cannot sign a Finding, create a verifier attestation, update native T4/T5 Evidence status, grant local approval or reach a protected writer. `InventoryItem(purl, version)` stays exact. Advisory ranges, aliases, backports and ambiguous inventory produce `unknown` or unsupported observations, never an inferred exact match. Diagnostic observations have no authority bridge.

## Unresolved Scout–Investigator adapter contract

The currently separate Scout and Investigator worktrees each define a private type named `AdvisoryInput`; they are **not the same contract**. Scout's record identifies a source revision and priority, while Investigator's input includes an `Asset` and `SourceSnapshot` tuple. No automatic coercion is authorized.
