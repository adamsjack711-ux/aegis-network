# Phase 5 read-only intelligence orchestration

**Integration reference:** `8292e531194216a578c32c912d066f98cdbce9ea`. This document freezes the current authority boundary and assigns private, versioned adapter proposals for the next cycle. It does not adopt a new signed protocol or authorize a network feed or model call.

## Data path and authority

`local pinned advisory bytes → authenticated/declared source snapshot → deterministic parse and deduplication → scheduled research task → deterministic baseline and optional bounded provider hypothesis → independent source-point check → ResearchReview → read-only display`. Every stage records input digest, source identity, parser/reviewer version, run ID, time and explicit unknown or inconclusive state. A URL, hash or model citation alone is neither source authentication nor proof that a claim is true. Withdrawal, correction and expiry invalidate cached research keyed by source digest and source-status cut. Scheduling is local, offline and idempotent until a live feed receives separate review.

`SourceSnapshot`, `Claim`, `Asset`, `ResearchResult` and `ResearchCheck` in `src/aegis/intelligence/` are existing **private v1/v2 runtime records**, not shared Evidence or Mesh contracts. The earlier `AdvisoryInput.v1`, `ResearchCandidate.v1`, `ResearchCheck.v1` and `ResearchReview.v1` names in [Phase 5A architecture](phase5a-architecture.md) are **provisional proposals**; they do not field-map to runtime classes automatically. Scout may produce the existing `SourceSnapshot` plus normalized `Claim` tuple from local fixtures. Investigator may consume a frozen snapshot/claim tuple and the existing `JSONProvider` boundary to produce quarantined research. A cross-lane adapter needs a versioned field map, old/new readers, content/source hash checks and independent negative tests before adoption.

The only authoritative defensive network finding remains `SignedFinding 1.0` in `src/aegis/artifact.py`; its canonical bytes, grants, expiry and revocation are frozen. A research check can mark a hypothesis consistent with supplied bytes, but cannot sign a Finding, create a verifier attestation, update native T4/T5 Evidence status, grant local approval or reach a protected writer. `InventoryItem(purl, version)` stays exact. Advisory ranges, aliases, backports and ambiguous inventory produce `unknown` or unsupported observations, never an inferred exact match. Diagnostic observations have no authority bridge.

## Evaluation and gates

VAL freezes a local corpus with authenticated/synthetic provenance labels, unknown and withdrawn cases, malformed and prompt-injected advisories, duplicate IDs and corrections. Compare deterministic and model arms on identical eligible cases with explicit planned/attempted/eligible/abstained/failed counts, false affected/false unaffected, point-level semantic support, p50/p95 latency, CPU/token usage and actual billed USD if a model call is separately authorized. Scripted or mock answers show pipeline behavior, not real-model improvement. A model experiment requires exact snapshot/model ID, outbound bytes/hash, destination and redirect rules, maximum calls/tokens/USD, separate credential custody and a provider billing oracle; a caller-written approval JSON is insufficient. No such experiment is authorized now.

The end-to-end read-only acceptance path is a local synthetic advisory through Scout, deterministic check, quarantined mock Investigator, independent source review and CLI display with `independent_status=unknown`. Every stage must be digest-linked and auditable without a Mesh sign, Evidence status mutation, local approval or protected write. Unavailable inputs and unsupported versions stay inconclusive. Results are demonstrated only when an independently run exact integrated test records the full path.

## Pending Scout–Investigator interface review

The currently separate Scout and Investigator worktrees each define a private type named `AdvisoryInput`; they are **not the same contract**. Scout's record identifies a source revision and priority, while Investigator's input includes an `Asset` and `SourceSnapshot` tuple. No automatic coercion is authorized. A proposed adapter must take the exact Scout event/revision and retrievable source bytes by digest, independently verify source identity and current/withdrawn state, obtain a local inventory `Asset` through the observation-only path, and bind all three digests in a new private run record. The adapter may schedule research only; it cannot construct `SignedFinding`, local approval or a protected-writer request. Main and VAL review a clean versioned mapping with golden old/new fixtures before intake.

That is **not** the frozen out-of-band, one-use operator authorization, even if it checks model and corpus strings. Keep the provider and all real transport paths isolated; the offline scripted path can be reviewed separately. This is an early interface observation pending independent review, not a final owner verdict. No external model call is approved.
