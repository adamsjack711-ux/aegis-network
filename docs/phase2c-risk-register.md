# Phase 2C hardening risk register

Status at the dry-run review handoff. Severity describes the consequence if this lab design were relied on more broadly; no mitigation execution exists.

| ID | Severity | Risk and current boundary | Required next gate |
| --- | --- | --- | --- |
| R-01 | High | UUIDv4 IDs make accidental collisions negligible and a JetStream KV compare-and-swap lease stops two active processes on **one broker account** from sharing a durable. NATS has no authentication or per-agent ACL in this Compose lab; an actor with broker access can claim, delete, or spoof leases. A cloned ID on a different broker is not detected. | Enroll deployments with separately authenticated agent credentials and a trusted registry or cross-cluster identity authority; test clone and takeover across brokers. |
| R-02 | High | The PostgreSQL journal permits recovery after JetStream stream loss. The replay HTTP endpoint is unauthenticated and a compromised coordinator can omit or reorder signed events. Local signature checks prevent forged allows, but cannot prove completeness. The agent stops on a detected replay gap or invalid revocation. | Authenticate replay clients, add an independently witnessed hash chain or transparency checkpoint, and test withheld pages and coordinator rollback. |
| R-03 | High | An old v1.0 revocation lacks a signed target publisher. New ingestion rejects it; already committed legacy ledger entries remain effective as denials. Lost old revocations cannot be safely reconstructed under the new scope contract without reissuance. | Inventory old revocations, issue v1.1 replacements with explicit scope, and rehearse audit/volume migration before deployment. |
| R-04 | High | A revocation can be replayed after its envelope expiry while its local grant is currently valid. Expired or locally revoked grants cannot validate old revocations, so a long-offline agent may halt or miss a withdrawal if trust history was not preserved. | Define signed historical trust snapshots and key-compromise semantics; test offline recovery across key expiry and rotation. |
| R-05 | High | The event journal is in one PostgreSQL instance with no tested backup, high availability, or retention plan. Loss or truncation of both journal and stream defeats automatic catch-up. | Back up and restore PostgreSQL plus agent SQLite state; test journal rollback, WAL recovery, and total broker/database loss. |
| R-06 | Medium | Findings stream is file-backed with 24-hour max age, 64 MiB cap, and discard-new on capacity. PostgreSQL outbox retains a rejected publish for retry. A full stream can stall delivery; stream age can remove data before an agent reconnects. | Add lag, capacity, outbox-age, and replay-cursor alerts; load test 100-agent backlogs and size retention from measured outage budgets. |
| R-07 | Medium | Dead letters use a separate file-backed 7-day/64 MiB stream. Malformed input is terminated only after dead-letter publish. After five audit failures, findings are dead-lettered and terminated; failed revocations remain unacknowledged for retry. If the dead-letter stream is full or unavailable, poison input retries indefinitely. | Add operator alerting, access controls, review cadence, and a signed/manual replay procedure; test DLQ exhaustion and redrive. |
| R-08 | Medium | Revoker scope is an explicit set of target publisher IDs. A revoker may sign a target ID/digest that is not present at ingestion; local exact digest and target publisher matching prevents it from withdrawing another publisher's finding. The coordinator does not yet verify a present target's digest or publisher before accepting the revocation. | Validate known targets at ingestion, document cross-publisher authorization governance, and test target-ID collisions. |
| R-09 | Medium | Historical SQLite `allow_dry_run` rows remain after expiry, local policy tightening, or revocation. Effective local reads recheck trust and use denial ledgers, but raw audit readers could mistake history for current authority. | Version a signed audit export with explicit historical and effective fields; prohibit executor use of raw rows. |
| R-10 | Medium | A signed finding authenticates a publisher, not the truth of its evidence. No isolated verifier, attestation, or external audit integrity exists. | Specify independent verifier attestation and evidence binding before any execution design. |
| R-11 | Low | The current single-host benchmark has one run and 20 findings per scale. Simulated consumers do not acquire runtime identity leases. It cannot establish multi-host availability, hardened runtime latency, long outage recovery time, or a mitigation latency target. | Repeat under varied load, failures, and independent hosts with confidence intervals. |

The active code remains dry-run only. None of these rows grants permission for mitigation, production targets, or Daybreak integration.
