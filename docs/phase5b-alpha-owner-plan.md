## Contract and file ownership

This lane owns only the CLI, its local signed-event and inventory adapters, private observer-specific publisher-grant loading, packaging metadata, CLI documentation, tests, and raw alpha benchmark files. The integration lead owns any shared contract change. VAL-D owns independent oracles and must not use the owner's tests as sole proof. Do not edit `artifact.py`, `core.py`, native T4/T5, Mesh, Rapid, mitigation, protected writers, or other agents' worktrees.

Preserve `SignedFinding` / `Finding.schema_version="1.0"` and original Ed25519 canonical bytes. Preserve exact `InventoryItem(purl, version)` comparison. The `mesh-events-v1` file remains a local input adapter, not a shared feed contract or evidence proof. Private CLI `inventory-v2`, `status-v2`, `observation-results-v2`, `exposure-observation-v2` and `doctor-v2` remain private outputs with no silent v1 alias. A signed exact package match must carry distinct `publisher_authenticity=verified`, bounded `local_claim_status`, `software_match=matched`, `independent_status=unknown`, and `overall_assessment=unknown`. The CLI accepts no current independent T4/T5 proof in this alpha. No result grants local approval or target authority.

The source import graph currently reaches dry-run `core.py` through `cli -> intelligence_adapter -> config -> core`. Independent review found no protected-writer call, but this is separation debt. After oracle freeze, propose an observer-specific publisher-grant parser that depends only on `trust.py` and `artifact.py`, with golden acceptance/rejection equivalence tests against `config.load_publishers` at the reviewed pin. Do not weaken role, key expiry, revocation scope or duplicate-grant handling. If exact equivalence cannot be demonstrated without editing shared config, retain source-only scope and submit an interface proposal instead of silently forking trust semantics. The installed package's other modules remain present unless a separate observer wheel is reviewed; an import boundary alone is not package-content isolation.

## Implementation order after VAL-D freeze

1. Pin the frozen oracle commit, image IDs, fixture hashes, offline wheelhouse and supported Python minors. Use only cached build/runtime dependencies and `--offline`; absence of Hatchling or an image is a recorded skip, never a network fetch or passing test.
2. Extract only the CLI's local grant parsing path from the `config -> core` import chain, preserving TrustStore checks. Add direct import-graph and golden grant tests before enabling packaging. Keep malformed, oversized, future, expired, revoked and contradictory signed inputs rejected or unknown under the existing v2 output rules.
3. Restore `[project.scripts] aegis = "aegis.cli:main"` on this branch only. Build an offline wheel in disposable storage, inspect its metadata and installed files, install with dependencies from the pinned local cache, invoke the generated console script **directly** under an ordinary UID, and uninstall. The previous `/tmp` noexec workaround interpreted the script with Python; that is insufficient for the direct-entry-point gate. A disposable executable test mount may be used with `--network none`, read-only root, no capabilities and no-new-privileges. Record it explicitly.
4. Run the default and failure-path no-write matrix on the installed wheel, with `--state-dir` as the only persistence opt-in. Compare full writable-tree paths, content hashes and mtimes before/after. Test user-controlled ancestor/final symlink rejection and mode 0700/0600; record race-resistance as unproven unless a concurrent-local-actor test supports it. Keep `PYTHONDONTWRITEBYTECODE=1` or a read-only installed package mount in the declared harness.
5. Use separately pinned cached Debian and Ubuntu images for real non-root inventory and signed-claim fixtures. A Debian image with a synthetic Ubuntu `os-release` file tests parsing only; it is not an Ubuntu installability result. Unsupported RPM and derivative distributions remain unknown. No image pull or external advisory request is authorized.
6. Request VAL-D independent exact-pin wheel, console, no-write, signed-status, import-graph, adversarial I/O, and resource challenges. Only then propose entry-point intake to integration. No production distribution or autonomous enforcement follows from alpha acceptance.

## Open decisions for integration review

- Whether installable alpha may ship the full `aegis-network` wheel after runtime import isolation, or requires a separate observer-only distribution that excludes enforcement modules entirely. Avoid changing shared project dependencies without a reviewed package split.
- Whether VAL-D can supply a cached syscall tracer and an independent Ubuntu image without network access. If not, score those gates inconclusive or skipped, not passed.
- Which Python 3.12+ minors are actually supported by cached wheel/ABI evidence. The project metadata's broad `>=3.12` range is not itself a tested matrix.
- Whether immutable, authenticated native T4/T5 status can ever be supplied to a read-only observer. It requires a separate reviewed adapter and roots; this alpha continues to emit `independent_status=unknown`.
