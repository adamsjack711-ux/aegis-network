# Phase 4E-C Independent Witness and Evidence Status

This prototype exercises separately configured trust services across nine local processes against the approved Phase 4E baseline `ae59a97becfdbf9fb79c7cc89c0a27c662fb9a9f`. A disposable SQLite writer commits a reviewed canary, refreshes trust before a peer write and preserves the recorded restrictive canary and its original expiry after revocation. The prototype is additive and shadow-only relative to the shared Phase 3C/T6 writer. Integration with Phase 4E withdrawal dispatch, ownership fencing and the live target transaction remains a release gate. [Implementation](../src/aegis/phase4e/) · [Adversarial tests](../tests/phase4e/test_trust_services.py)

## Foundations and dispositions

- T2 calls for admission outside the coordinator, retained receipts, bounded freshness, historical replay and independently pinned status. Phase 4E-C uses one policy-scoped cut across Mesh and Evidence, preserving their native signing bytes. The checkpoint certificate and nonce-bound response serve different purposes. [T2 research](../../../docs/research/aegis-trust-transparency.md)
- T4 provides Ed25519 admission and coverage records, RFC 9162 Merkle primitives, quorum verification and the pinned witness ledger. The services reuse those primitives. The bounded Phase 4E-C archive commits the original Mesh and Evidence bytes with their receipt. Complete replay reconstructs the tree, checks each record, and verifies extension against observed heads. Separate inclusion proofs serve receipt monitoring. [T4 report](phase4d-journal-integrity.md) · [RFC 9162 §2.1](https://www.rfc-editor.org/rfc/rfc9162.html#section-2.1)
- T5 provides exact material and worker profile appraisal, independent verifier organizations, bundle and key withdrawals, and durable contradiction semantics. The publisher signs a recomputed result and the writer independently recomputes it from the archive. Original manifests, observations and withdrawals retain their format. The common cut uses 3-of-4 witness coverage. A single direct intake can leave three witnesses eligible to endorse an older cut, unlike the previous all-mandatory two-operator T5 lane. Existing writer semantics stay in force pending integration review. [T5 report](phase4d-t5-evidence-status.md)
- 4C-01 and 4C-04 receive local service and custody-boundary prototypes. 4C-02 remains with the independent ownership and fencing workstream. T6 demonstrated the combined writer, restrictive readback and an unresolved withdrawal reporting bound under agent restart. Phase 4E-C does not repeat the broker, distributed ownership or nine-route tests. [4C findings](phase4c-adversarial.md) · [Phase 4D release readiness](phase4d-release-readiness.md) · [T6 validation record](../../../docs/phase4d-validation.md)

## Fault and collusion model

Four pinned witness signing keys represent four declared administrative domains. With quorum three, two quorums intersect in at least two members. If at most one witness domain is Byzantine, at least one honest witness belongs to both. An honest witness retains intake and seals in its independently anchored ledger, certifies only extensions, and refuses a cut missing any locally promised record due by that cut. The same intersection argument applies between a quorum receipt and a checkpoint at or beyond the receipt's epoch. Three reachable, converged witnesses can issue a cut and fresh views. A pending or newer divergent view, slow network path, coordinator refusal to order, unavailable archive, or unavailable publisher or anchor can reduce availability. Unavailability removes the ability to start a protected write at the next refresh.

Two arbitrary witness signers can sign both proposals, using a different honest signer for each. This creates two individually valid 3-of-4 certificates. If a reader sees both contradictory views, it retains both signed proposals and holds. Isolated readers might each see only one fork. Enrollment rejects duplicate keys, duplicate declared administrative domains and cross-role ownership overlap. These checks trust the inventory and cannot detect hidden shared ownership, shared privileged operators or collusion. A misleading inventory can invalidate the quorum argument.

Process separation was exercised locally. Witnesses, checkpoint proposer and status publisher have distinct signing keys and configuration. The two archives have distinct stores and credentials. Each witness issues both receipt and checkpoint coverage votes under distinct signature domains. The checkpoint proposer supplies an independently keyed proposal and cannot certify its own cut. The anchor has its own process, database and per-namespace credentials. Native publishers, verifiers and revokers have distinct role, issuer and key-bound admission credentials. The fixture provisioner, OS account and physical host can access the entire disposable topology. Actual administrative independence requires verified independent key custody, separate operators and privileged accounts, independently managed restore domains, separate network and time dependencies, and evidence that those controls are exercised. All keys and tokens used here are generated in temporary fixture paths and removed on teardown.

The trust argument assumes Ed25519 unforgeability, SHA-256 collision and second-preimage resistance, trusted bounded UTC and monotonic clocks, correct pinned roles and policy, and continuity of honest witness and relying anchor state. The coordinator and archives can withhold, order incorrectly or return bad proofs. The status publisher can withhold or lie, and a signed assertion alone grants no authority. Two verifier organizations support a native Evidence outcome. Their signatures attest provenance and exact observations under their enrolled controls. Independent witnesses attest history coverage and cannot make a false verifier observation true. [Ed25519 library documentation](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/)

Coverage is about the records submitted and receipted under the enrolled policy. The protocol cannot prove that no unpublished withdrawal exists. A record with fewer than three matching admission signatures has weaker coverage and can be bypassed until the relevant seal or quorum. A fresh reply delivered just before new intake can race the local commit. Per-write refresh, nonce binding and short monotonic deadlines bound the window under trusted time. They do not make revocation atomic with writes on independent targets.

## Contracts proposed for integration

| Contract | Prototype behavior and integration requirement |
| --- | --- |
| Enrollment and transport | Pin one policy context per cohort with exact keys, roles, administrative domains, native historical grants, worker profiles, quorum and time bounds. Witness `POST /admit` requires an operation credential bound to the native issuer and key ID as well as a valid original signature. Verifiers can submit observations and revokers can submit scoped withdrawals. Independently authenticate transport, separate endpoint namespaces and issue per-role credentials in the deployment. The disposable service uses bearer capabilities over private Unix sockets. A deployment needs mutually authenticated transport, reviewed identity mappings, independent custody and priority admission. |
| Direct intake and receipt | Send original bytes directly to all enrolled witnesses, retain three matching T4 admission votes on context, epoch and the tagged wire digest, and reconcile exact originals using `GET /receipts/{epoch}/{event}`. Receipt voters durably append before responding. Each witness reserves eight of 256 distinct intake slots for withdrawals. The archive reserves the same number. When a new authorized withdrawal cannot fit at a witness, its anchored exhaustion latch stops local fresh views. An unresolved or partial admission can require retry or operator reconciliation. Receipt certification alone does not prove inclusion. |
| Checkpoint and mirror | A separately keyed proposer signs `Head(context, epoch, size, root)` via `POST /propose`. Ordering may be coordinated, while acceptance takes three witness signatures via `POST /seal`. Witnesses verify consistency, complete archive data and individually promised records. Epochs are sealed against the conservative UTC sample. Archive `/snapshot/{size}` returns ordered certified leaves. `/proof/{size}/{index}` returns an inclusion path. The digest-verified full prefix yields RFC 9162 consistency proofs locally. Production transport should use bounded pages and compact proofs before scale testing, and keep a separately polled receipt and fork monitor. Preserve observed inclusion time alongside signed conflicting proposals. |
| Evidence status | The writer generates `Challenge(context, subject, nonce, issued_ms)`. The subject binds audience, exact signed Mesh finding, Evidence cohort, exact bundle, claim, material scope and environment. Obtain challenge-bound `/view` responses directly from pinned witness endpoints and require a quorum for the highest observed cut. The independent publisher obtains its own views and replay and signs `Status(challenge, head, outcome, reason, attestations, expires_ms)` with the pinned status key. The writer validates its own material bytes and recomputes the result. A mismatched, unavailable, conflicting or obsolete publication cannot authorize a write. Expiry is bounded by challenge, cut, finding, grants, manifest and qualifying observations. Re-signing an obsolete cut cannot refresh its cutoff. |
| Checkpoint and status persistence | Each witness chains admitted records, exhaustion and sealed cuts to a separate anchor namespace. Each publisher and writer maintains an anchored floor with a verified cut, an unresolved newer cut and signed fork evidence. A newer quorum cut persists before replay. A failed replay leaves the higher floor pending, including across restart. The anchor is authoritative relative to restored archives and witness ledgers. Its lab SQLite compare-and-swap does not protect against rollback or takeover of the anchor itself. Deploy an independently controlled monotone anchor with audited restore and test each failure domain. The witness's local write precedes external CAS. If a crash strands those writes, recover the exact anchored prefix under an authenticated recovery procedure. The service stops when state and anchor disagree. |
| Key history | Restore and verify native signatures against a pre-enrolled historical roster and receipt epoch. Rotation tests retire the old Mesh and Evidence revoker keys and use pre-enrolled successors in the same pinned policy. Replay preserves old valid tombstones. New direct admission checks the role, arrival window and live grant, so a retired key cannot create a new receipt. The Mesh lane rejects compromised grants overlapping the relevant receipt epoch. An authenticated policy or witness-roster handover, post-enrollment compromise adjudication and recovery across policy generations need separate versioned contracts. |
| Protected write | Each new write calls `Gate.refresh` and consumes one verified status through `Gate.authorize(status, reviewed_binding)`. Bind the reviewed status digest to the approved exact action, targets, assignment generation, fence inventory and deadline at the existing writer. Check current status and fence again inside the target transaction before commit. An empty epoch changes the cut binding and requires renewed review under this prototype. Latch an interrupted plan at the existing writer and require explicit review before resuming. A later denial preserves only restrictions independently verified safe under the applicable safety and expiry rules. Restore or replay must never extend a safe restriction's original expiry. |

A fully authenticated archive makes an incompatible prefix detectable even when checkpoint sizes differ. Invalid or missing archive data instead leaves the reader unable to establish continuity. Missing inclusion at the deadline is a missing-proof observation. A later valid proof can establish inclusion after that observation and cannot backdate the proof's delivery.

## Adversarial evidence

| Fault | Checked result |
| --- | --- |
| Coordinator omits a quorum-receipted Mesh withdrawal | Fresh status holds immediately after receipt from three witnesses, and the omitted next proposal gets one signature. The monitor reports missing proof at the deadline. Mirror inclusion and later status establish the withdrawal. |
| Coordinator proposes a Merkle fork | Three honest votes certify one proposal and only one honest witness signs the other. Two simulated colluders can make the second certificate pass signature verification. Observing both proposals latches a durable conflict. Declared shared ownership is rejected. |
| Evidence revoked during canary | Fresh read after direct admission prevents a peer commit. Inclusion confirms `revoked`. The durable fixture contains only the original canary and its unchanged safety expiry. |
| Status signed over an obsolete checkpoint | A correctly signed obsolete publication fails independent appraisal. The newer checkpoint floor persists even when the publisher is rejected. |
| Old revocation key replay | After both revoker rotations, new intake using the old credentials and signed withdrawals fails. Historical receipt recovery and the denial survive replay. The enrolled successor can admit a new scoped withdrawal. |
| Corrupt archive, mirror recovery and outdated restore | Two damaged archives leave the observed cut pinned as unresolved. Repairing the independently populated mirror restores the denial, an outdated witness ledger cannot start against the retained anchor, and a stale view cannot move the restored reader below its anchored cut. |
| Loss of quorum and isolation beyond freshness | One stopped witness preserves fresh status. Two stopped witnesses cause a hold. The prior verified status cannot be used after its monotonic deadline while all status paths are isolated. |
| Credential misuse, scope substitution and capacity | Publisher and verifier credentials cannot submit another issuer's withdrawal. Wrong audience and environment cannot grant authority. Capacity tests exercise the reserved withdrawal slot and a durable exhaustion latch. |

The 2026-11-19 full default suite passed 278 tests, including all nine Phase 4E-C tests. Three opt-in Docker cases were skipped. The run reported the inherited Starlette/httpx deprecation warning.

## Reproduce from a terminal

Run from the requested worktree with the project's Python 3.12+ test dependencies available. The scripts bind only private temporary Unix sockets. Docker and external endpoints are outside this verification.

```sh
cd .worktrees/phase4e-trust
git rev-parse HEAD
PYTHONPATH=src:. python -m pytest -q -p no:cacheprovider tests/phase4e
PYTHONPATH=src:. python scripts/benchmark_phase4e_trust.py \
  --sizes 4 32 128 --repeats 12 --output benchmarks/phase4e-trust.json
```

Use `python -m aegis.phase4e.service <role-config.json>` to start one separately provisioned role on an enrolled private Unix socket. The [fixture provisioner](../scripts/phase4e_lab.py) builds the per-role settings, initializes the anchor namespaces and launches a complete topology for the test and benchmark. Use its ephemeral provisioning for reproduction. It centralizes fixture material and is unsuitable for enrolling real authorities.

## Measurements

See [raw benchmark samples](../benchmarks/phase4e-trust.json). Every timed healthy path checks its expected positive result, and every denial arm checks that authority was withheld. Each size has one provisioned topology and repeated warm samples, with one functional revocation transition and one mirror replay. The availability counts are controlled outage observations. They are unsuitable as production availability estimates. CPU includes service startup, workload and teardown. Credential generation and preparatory configuration are outside the timed trial. RSS is summed across nine service processes and can count shared pages more than once. Storage is measured from SQLite files. The prototype uses full replay and does not establish a production capacity or network-to-denial bound.
