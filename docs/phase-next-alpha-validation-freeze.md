## Universal trial rules

1. Run only on authorized, disposable localhost or cached container fixtures. `--pull never`, `--network none`, synthetic throwaway signing keys and no external feed/provider/host/real credentials. A missing local dependency, image, tracer, enrolled model, witness or credential is **skipped/inconclusive**, never silently replaced by online retrieval.
2. Pin candidate full commit, dirty state, source and harness SHA-256, input fixture SHA-256, image IDs, OS/architecture, Python version, exact command, agent roster, event IDs, attempted operations, raw output and exit status before scoring. Keep predecessor failing files and any new failed run even if a later trial passes. Neither a passing focused suite nor a broker ACK is an independent end-to-end safety result.
3. Score `pass`, `fail`, `inconclusive` or `skipped` per case. Fail is an observed violation with a usable independent oracle. A missing or incomplete observation is inconclusive. An unavailable prerequisite is skipped. Report the **planned, attempted, eligible, observed and censored denominators**, with reasons for every omitted sample. No aggregate p95 may hide a single all-agent failure.
4. Use monotonic time within a process and, only when the OS guarantees a common monotonic clock, across processes on the **same host**. For separate hosts record independently observed timestamps plus measured clock-offset/error bounds; do not subtract unsynchronized wall clocks. Report interval lower/upper bounds from polling. Store UTC wall timestamps for audit correlation, not for unbounded latency subtraction.

## 5B installable observation CLI alpha oracle

**Minimum matrix:** two **real** cached Linux distributions (Debian and Ubuntu) × twelve default-mode commands = **24** default invocations, plus four explicit-state controls per distribution = **eight** opt-in controls. The twelve default commands per distro are: `status` without feed; `inventory`; `findings` without feed; `findings` with a missing file; `doctor`; `explain` without feed; `findings` with signed current exact match; signed expired; signed withdrawn; unsupported exact/range identity; malformed or tampered signed file; and incomplete or duplicate inventory. Every row records JSON and human output where applicable, exit code, filesystem tree before/after including content hash and mtime, and network/process/privilege syscalls. Invalid signature or publisher grant, future, revoked and conflicting local events are additional negative controls; their counts are reported separately. The eight opt-in controls are first identity creation, stable repeat, user-controlled symlink ancestor rejection and final-path symlink rejection in each distribution. Default mode requires **zero created or modified files** in all declared writable mounts (XDG, HOME, tmp and package state), including errors. Explicit `--state-dir` may write only a 0700 directory and 0600 UUIDv4 identity inside the canonical requested path. A system symlink alias exception must be exact and root-owned; a concurrent local path swap remains an explicit race limitation unless independently controlled.

The wheel must be built offline from a clean pin with locked cached build/runtime dependencies, installed into a fresh non-root environment in each distro, invoked through its packaged `aegis` console entry point, and uninstalled with no service or post-install action. Verify wheel metadata, entry point, bundled modules and dependency list; an old preinstalled `aegis-network` in an image must be isolated or force-replaced. A wheel built without an entry point fails **installable CLI alpha** even if `python -m aegis.cli` works. A local cache miss is a skipped packaging gate, not permission to fetch. Measure 100, 10,000 and 100,000 package-row inputs with **three fresh trials each per distro**, reporting elapsed, CPU and peak RSS per trial and zero unbounded growth or crash. A resource threshold must be published before comparative scoring; until then report the envelope as descriptive, not a pass.

Every signed observation must keep `publisher_authenticity` (signature/grant), `local_claim_status` (only supplied-file/time), `software_match` (exact package only), `independent_status=unknown` and `overall_assessment=unknown` separate unless a separately reviewed native T4/T5 proof adapter is present. The CLI must not load enforcement or native writer modules (`aegis.mitigation`, `aegis.agent_runtime`, native target services) or call their APIs/sockets; source import-graph inspection and guarded execution are both required. The existing `config -> core` type import is known separation debt; for an installable alpha require a reviewed independent grant-loader boundary or document a narrowly justified import exception with a no-side-effect oracle. Python-level socket guards and `--network none` do **not** prove zero attempted connections. Use a **pre-cached** syscall tracer inside an otherwise restricted container to record connect, exec, privilege and writable file operations. If no tracer is available, the syscall gate is **inconclusive**, even if filesystem snapshots pass. No package-manager or system-service writes are authorized by a CLI invocation.

Reproducers already frozen: `scripts/phase_next_probe_cli.py` (five-case default paths), `scripts/phase_next_5b_status_challenge.py` (signed/current/negative v2), and `scripts/phase_next_5b_linux_state_probe.py` (explicit state). The prior `scripts/smoke_phase5b_{install,linux}.sh` still require a console entry point and are **expected unavailable at baseline `3bfd2ab`**. Run them only against a reviewed successor that restores packaging. Preserve their stdout/stderr and exit codes; do not treat expected baseline failure as a regression. No external image pull or dependency install is allowed.

## 4F withdrawal and fencing oracle

**Minimum controlled denominator:** three enrolled dry-run agents × two valid, independently witnessed withdrawals (independent revoker and mixed publisher sequence) × three fresh repeats × four arms = **72 targeted agent-withdrawal pairs**, plus three-agent/two-withdrawal/three-repeat healthy broker-restart controls = **18** control pairs. The four arms are (1) SIGKILL before agent intake + broker restart + six ordinary pending outbox rows, (2) broker/network partition and rejoin with the same backlog, (3) lost ACK after local durable decision with replay, and (4) stale owner versus new owner generation during withdrawal delivery. These are **minimum local simulated** denominators, not physical multi-host evidence. Each run declares roster, broker/witness availability, signed event IDs, affected target inventory, owner generations, local approval expiry and planned partition duration before injection. Record all enrolled pairs, including crashed/offline actors. If an agent never reconnects or Trust proof remains unavailable, report that pair separately as censored/inconclusive and the all-agent release gate **cannot pass**.

For every pair, measure controller submission → PostgreSQL commit → outbox eligibility/publish → independent T4 inclusion and current T5 withdrawal status → broker availability/receipt → signature/trust evaluation → **independent read-only SQLite durable denial** → ACK/cursor. Report submission-to-denial as the inherited primary metric and witnessed-acceptance-to-denial plus restored-connectivity-to-denial as additional metrics. Planned isolation never silently resets the primary clock; if an arm intentionally exceeds five seconds of disconnection, its primary gate fails or remains explicitly censored. A valid ACK, replay cursor, HTTP receipt, existing target hold or coordinator message cannot substitute for independent current status or the affected agent's committed denial. The five-second all-agent gate passes only when **every eligible connected pair's conservative latency upper bound ≤5,000 ms**, with zero omitted agent and zero unauthorized positive write; report the maximum and p50/p95/p99 separately. A one-agent pass cannot close this gate.

Before and after faults, independently read each protected target and all declared routes **before observer traffic**. The target must retain a restrictive hold across crash, broker failover, partition and restart. Test stale signed owner commands, competing writers, delayed/reordered withdrawal, restored snapshot, expired lease, revoked Evidence and contradictory/incomplete Trust. A successor's generation must be durably greater; all protected writers must reject the predecessor, and broker ACK/cursor advancement must be bound to the current generation **after** the local decision commits. Validate same exact plan, local approval, target identity/fence, earliest expiry, Evidence cut and native T4/T5 status in the protected transaction. Unknown status blocks new positive authority. No automatic rollback may reopen the known vulnerable route. Record zero duplicate logical denials and zero lost withdrawal/replay obligations. Keep physical multi-host ownership, independent witness custody and external monotonic rollback anchors open until authorized hosts are enrolled.

The original `scripts/phase4e_withdrawal_recovery_check.py` with `--kill-agent --priority` reproduces the predecessor, and `scripts/phase_next_4f_stage_audit.py` scores recorded diagnostic stages. The initial validator stage score had an **oracle-key error** (compared target finding IDs with withdrawal IDs); its raw score and the corrected score are both retained. A successor must use target finding IDs for effective denial and withdrawal IDs for delivery, without erasing either original trace. Owner-generation, ACK/cursor and T4/T5 checks require new independent oracles at the exact successor pin; existing one-host Mesh dry-run traces alone are insufficient.
