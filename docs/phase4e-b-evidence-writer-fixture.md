# Phase 4E-B Evidence-bound writer fixture

This additive fixture combines the native T4/T5/Rapid lab appraisal from `ae59a97becfdbf9fb79c7cc89c0a27c662fb9a9f` with B's protected SQLite marker transaction at `79f068a09f7b76f546f6f6780043ff1ae1ec01b9`. The caller configures the appraiser locally with the native gate and prepared plan. The fixture verifies independently witnessed Mesh history, the exact finding, Evidence bundle and attestations, independently endorsed Evidence status, and the matching Rapid audit deployment. The broker has no path to select a proof or verify it on the writer's behalf. [Writer contract review](phase4e-b-writer-contract-review.md)

The configured local operator signs a new private versioned approval covering the native plan digest, exact Mesh checkpoint and Evidence status bindings, and original B mutation. The B mutation includes the target, owner generation, assignment, and expected writer version. The writer independently validates both the original B signatures and the supplemental exact approval. It checks the native cut and native monotonic deadline from within B's SQLite transaction. The same native guard remains open through B's final ownership RPC and commit. [Fixture source](../src/aegis/identity_lab/evidence_fixture.py)

B's existing transaction checks its wall-clock credentials, assignment, command and approval deadlines. The fixture pins the earliest native operational freshness, finding validity, plan and supplemental approval monotonic deadline while the native guard is held. A connection-local SQLite authorizer checks the pinned cut and timing when SQLite prepares the explicit `COMMIT`, after the final ownership RPC and while B holds its loss mutex. After the native status read it resamples monotonic time and also checks the exact wall-clock assignment window, capped by the command, both credentials and original B approval. A denied commit rolls back the requested marker update and original command receipt together. The tested writer opens a fresh SQLite connection for each mutation. [SQLite authorization callback](https://www.sqlite.org/c3ref/set_authorizer.html)

## Test results and boundaries

The nine disposable loopback cases passed. They cover exact approval, wrong local signer, different cut, different native plan, wrong target, a stale owner generation, and replacement of the approved checkpoint. In two controlled probes, the writer staged the marker and receipt and completed B's final mTLS ownership check before the test clock reached its exclusive cutoff. One used the shorter local approval deadline and the other the shorter native plan deadline. In both cases independent read-only SQLite inspection found the original marker, version and receipts. Reusing the same nonce under the healthy test clock then committed once. The same nonce then committed once under the healthy test clock. [Follow-up case results](../benchmarks/phase4e-b/evidence-writer-status-recheck-tests.json)

Two further tests cross the shorter operational native freshness window and the shorter forwarded B credential expiry during the final healthy native read. Both accepted the staged write before correction. Each now rolls back the marker, version and receipt, and the same nonce commits once under the healthy test clock. The fixture has a local-only entry point. The subclass rejects the ordinary B write entry point and no service instantiates the subclass. The test uses a locally supplied peer object at this entry point and real disposable mTLS services for the ownership claim and final home check. The writer's only effect is a synthetic marker. The guard reaches SQL preparation, with elapsed time during SQLite execution and disk flush outside the demonstrated bound. The fixture relies on the reviewed explicit-commit shape, fresh connection, and native guard locking. A production review would need an owned precommit contract, a durable native Evidence loss latch on the serving path, audited Evidence context, bounded clocks and remote-withdrawal delivery limits. Distinct operational trust custody and physical multi-host enforcement remain pending.
