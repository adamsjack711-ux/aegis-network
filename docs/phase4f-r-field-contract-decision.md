## Existing interface mismatches

1. **Direct discovery and completeness.** Native T4 `HTTPWitness.admitted(event, epoch)` requires the event coordinates and cannot discover a suppressed event. Its `head`/paged archive path verifies a sealed cut, which can omit an accepted withdrawal pending sealing. The proposed `DirectWithdrawalSnapshot.v1` has complete paginated, signed per-witness withdrawal-stream roots, nonce binding and terminal proofs, but no native implementation or reviewed encoding. The 4E-C `WithdrawalView` is a separate shadow profile with a 256-leaf cap and no paginated terminal proof. It cannot be substituted into native enforcement.
2. **Native status representation.** Native T5 returns an `inconclusive` assessment with reason `revoked` for withdrawn bundle/attestation/key. The proposal's T5 assertion that the specific Mesh withdrawal is `withdrawn` conflates Mesh and Evidence status: native T5 authenticates signed Evidence withdrawals and their exact scopes. A one-to-one Mesh Finding↔Evidence map and the actual Evidence withdrawal proof must be specified; a string reason, Mesh receipt or previously positive status cannot supply them.
3. **Agent audit transaction.** Existing `SqliteAudit.record_revocation` commits `revocation_decisions` and `revoked_targets`, but has no native proof-provenance table, store enrollment, rollback floor or v2 reader barrier. The proposed three-row atomic decision and `AgentAuditAnchor.v1` require a versioned migration and an independently held high-water mark. A copied local SQLite volume or a new field in an old database is insufficient. The exact existing `revoked_targets` table and `revocation_decisions` outcome must remain readable by the frozen independent oracle.
4. **Ownership and replay.** Current `IdentityLease.claim` waits for a broker KV lease and provides no cross-broker generation permission. Preclaim denial may run only as the enrolled agent with its canonical audit store and current independent native proof; it cannot authorize a target mutation or advance `critical_recovery_cursor`/ACK. Any later positive writer transaction must separately bind exact local approval, native Trust cut, target identity, owner generation, fence and earliest expiry. The preclaim proposal does not implement that barrier.
5. **Availability and metric.** The frozen 72 fault +18 healthy agent-pair oracle requires the agent's own committed denial within five seconds from both submission and witnessed admission, with 1,000 ordinary pending findings in every fault run. A target sentinel or generic unknown hold is a separate protection metric. A killed process, inaccessible canonical audit store or required native authority unavailable beyond five seconds makes the hard all-agent deadline unprovable in that arm; such pairs cannot be silently excluded. All-four fresh views can safely deny new positive authority during one-view outage but cannot count as a specific timely withdrawal denial without complete authenticated proof.

## Required revision and review gate

- Supply native T4 and T5 protocol versions with exact authority roster, signed bytes, completeness/consistency proof, bounded pagination and denial precedence. Define how one durably accepted exact scoped withdrawal is discovered when coordinator and broker suppress it, while avoiding denial power for an untrusted third party. Preserve the 3-of-4 sealed positive-history rule and independently administered T5 status.
- Specify cryptographically bound map enrollment, target/finding/Evidence identity, local policy/inventory snapshot lifetime, and audit-store custody. Distinguish fixture metadata from authenticated provenance.
- Specify the atomic agent-owned SQLite migration and separate rollback anchor with an old-writer exclusion barrier. Prove a restored snapshot or cloned agent cannot fabricate an on-time row or reopen a positive route.
- Give independent negative tests for forged/expired revoker, wrong Evidence digest, one required view lost, partial page, stale anchor, duplicate old/new process, stale signed owner, lost ACK, broker partition, withdrawal suppression and target rollback. Retain the 72+18 and 1,000 backlog denominator, read-only SQLite oracle, sound clocks, CPU/RSS and every failed/censored trial.

These are design and lab-test prerequisites, not permission to activate distributed enforcement. The existing fail-closed lease behavior and all original failure reproductions remain intact. Physical multi-host identity, independent authority custody and rollback-resistant anchor operations remain separate deployment blockers.
