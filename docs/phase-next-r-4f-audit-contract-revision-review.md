## Remaining contract blockers before implementation intake

1. **Latest accepted-withdrawal visibility under one faulty witness.** The request carries a *previous* anchored per-witness floor and verifies a fresh signed head against it. A witness that durably accepted and independently anchored a withdrawal could return a fresh, internally complete **older** head unless the agent obtains the latest protected floor from an independent authority or an authenticated cross-witness monitor. A challenge nonce proves response freshness, not completeness of the witness's newest obligations. Specify how each agent learns the current independent floor without a coordinator-provided event ID, how the floor is at least as new as the durable admission timestamp, and how a withheld current floor becomes an `unknown` hold. This is necessary for the promised one-witness denial precedence and coordinator-suppression case. An isolated malicious witness cannot be permitted to claim arbitrary permanent denial, but it also cannot silently hide a real authorized withdrawal.
2. **Native admission and obligation ordering.** The proposed `NativeDenialAcceptance.v1` is separate from existing native `Admission`/`Receipt`, as the document acknowledges. Specify exact atomic relationship among signed-envelope validation, witness ledger append, obligation-stream append, external floor anchor, receipt issuance and crash recovery. State which event is the independently witnessed submission and durable-admission clock start, and how a pre-receipt SIGKILL or partial anchor write is recovered. Publish byte encoding, domain, roster/epoch transition, replay/expiry, proof-size, timeout and failure-code rules with adversarial vectors before the new endpoint is used by a real agent.
3. **Exact Evidence digest names.** The proposed map calls `bundle_sha256` the SHA-256 of a “canonical native Evidence bundle”; current `Bundle.sha256` is `evidence.records.digest(bundle.manifest)`, the digest of the **signed manifest wire**, while material objects are individually pinned. `material_scope_sha256` is derived by `status_protocol.material_scope(manifest)` rather than a Manifest field. The text's `digest_bytes(claim_bytes(finding))` should name the reviewed `evidence.records.digest` function/encoding. Fix these definitions and cross-check golden vectors; an otherwise well-signed map with the wrong digest namespace cannot be accepted.
4. **Authority roster and denial policy.** Pin the exact native T4 witness policy, one-fault assumption, acceptance epoch and grant-retirement rule at the same effective cut as the T5 scope. State whether one authenticated receipt from an authorized revoker is enough for a *specific deny-only local audit* even if three witnesses have not admitted it; make clear this never becomes positive history or a coordinator-controlled arbitrary hold. Require all four current complete views or an independently reviewed equivalent. A required view/anchor unavailable is `unknown`, blocks positive writes, and **cannot** score an accepted withdrawal row.
5. **Canonical agent and all-writer migration barrier.** `audit_store_id`, path and host identity fields need an operator-enrolled, independently verifiable binding and a concrete enforcement barrier against a profile-1 process with the old file or target credentials. Define generation-bound ACK and critical/ordinary cursor schemas, target-home generation advancement, exact local approval and native T4/T5 check in the target mutation transaction. The preclaim path itself gives no positive write authority and does not prove stale-owner fencing or rollback safety. An anchor sharing the agent host/snapshot fault domain is not rollback-resistant.

The revised negative table correctly names coordinator suppression, T5-reproduced/Mesh-revoked separation, shadow-view rejection, malformed pages, expiry crossing, old-binary access and restored snapshots. They are **proposed tests, not passes**. The frozen release denominator remains **72 agent-owned fault pairs plus 18 healthy controls**, 1,000 ordinary pending findings in every fault run, independent read-only observation of each agent's own SQLite denial/provenance, and conservative upper bounds ≤5,000 ms for **both** witnessed submission→denial and durable admission→denial for every eligible pair. An unavailable canonical agent store, required witness view or replacement process is a miss/censored pair, never a target-proxy pass. The prior 30.559-second miss and 0/72, 0/18 unrun release matrix remain in force.

No authenticated multi-host enrollment, independent witness/anchor custody, complete rollback recovery, all-writer transaction, broad integrated regression or measured five-second result exists in this contract-only revision. Native T4/T5 remains authoritative; 4E-C remains shadow-only.
