They include idle ownership loss before observation, same-generation restore and restart, idle native status loss and recovery, a read-only route race against owner transfer, fresh-plan transfer, deadline rollback after staging, and explicit remote-after-final-check race controls. The result is scoped to the actual code and test on one host. [JUnit](../benchmarks/phase-next-validation/phase4f-native-focused.xml)

Maximum cut-to-hold readback was 20.208 ms for ownership and 27.904 ms for status. These are sampled one-host upper readback observations, not a service deadline. The benchmark driver belongs to the implementation branch; this independent run verifies its recorded state but does not replace a separately authored adversarial harness. [Ownership samples](../benchmarks/phase-next-validation/phase4f-owner-hold.json) · [Status samples](../benchmarks/phase-next-validation/phase4f-status-hold.json)

The native generation-bound broker ACK/cursor protocol, protected write behavior under independently administered Trust, physical multi-host rollback anchors, stopped-writer hold persistence, and the five-second all-agent withdrawal gate remain open. The owner explicitly records a remote status failure after the last local check that can precede the next denial. Distributed autonomous enforcement remains NO-GO.

## Linux CLI results and contract gaps

Six source-focused tests passed on `cc2e918` in 0.14 seconds. They exercise the existing signed Finding 1.0 parser, publisher grants, tamper rejection, scoped withdrawal, exact Debian version matching, unsupported ranges, partial inventory and a Python-level network denial. [JUnit](../benchmarks/phase-next-validation/phase5b-focused.xml)

A cached Debian arm64/Python 3.12.16 container at image `sha256:67898a5e53a2ebb1138a9e17b0dfb22e52aabca270854cf86d21372f179a003e` successfully imported the candidate source and ran `inventory --json` as UID 1000 with `--network none`, read-only root, no capabilities and no new privileges. It reported 87 installed packages. That is a source invocation, not a wheel installation. The cached image has neither `pytest` nor `hatchling`. The offline wheel smoke attempted against the local uv cache and failed because `hatchling` is absent. Installable packaging remains unverified in this independent run. The author's earlier wheel smoke is a separate observation.

The frozen observation-only contract and owner proposal conflict on default persistent state. In five independent invocations from empty state under the same offline Linux container, `status --json` with no feed, `findings --json` with no feed, `findings --feed` against a missing local file, and `inventory --json` each created `state/aegis/identity.json` without an explicit state option. Three returned exit 2 and one returned 0. `inventory --json` with explicit `--state-dir` created the ID only at the chosen path. This is a reproducible default write. The CLI has no protected target write, but a default observation can modify local filesystem state even when input validation fails. Review whether an ephemeral session ID or snapshot digest should be the default and whether `--state-dir` alone should opt into durable identity. [Raw five-case trace](../benchmarks/phase-next-validation/phase5b-default-writes.json) · [Independent probe](../scripts/phase_next_probe_cli.py)

A valid locally signed, currently timed lab Finding with an exact installed package emitted `result=matched`, `claim_status=current` and `verification=signed-mesh-v1-lab-scope` with no current native T4/T5 proof supplied. The only indication of missing independent status is a free-text `uncertainty` sentence. The output has no structured `independent_status` field. Keep the exact package match result if desired, but define `claim_status` as signed-claim time and local-file withdrawal state only and add a separately structured `independent_status=unknown` or equivalent. This preserves the separation between software match, claim provenance and current Evidence authority for machine consumers. It does not assert that the CLI authorized a write. [Raw signed-claim observation](../benchmarks/phase-next-validation/phase5b-signed-current-without-independent-status.json)

The CLI source imports artifact parsing, trust and local observation modules and exposes no mitigation or broker entry point. The Linux container ran with networking disabled. This is a narrow observation, not a complete syscall proof of zero outbound attempts or every supported package-manager behavior. Ubuntu, partial-inventory container variants, malicious local input file races, wheel installation and resource scaling remain independently unverified. An unsupported PURL or comparator yields `unknown` in the focused tests. A valid signed local file cannot prove complete Mesh withdrawal history, so no result should claim current independent status without the proof chain.

## Disposition

GO for continued isolated design and test of native proactive holds and the offline CLI. NO-GO for distributed native enforcement, closing the five-second gate, treating a signed claim as independently verified Evidence, or declaring the CLI installable across supported Linux environments. Resolve the two CLI contract gaps and packaging dependency before shared serialization approval. Preserve the Phase 4E failed full-suite XML and prior native ownership-order reproduction.
