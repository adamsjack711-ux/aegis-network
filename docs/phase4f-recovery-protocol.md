The frozen unit is **each pre-enrolled agent and withdrawal pair's own exact committed denial**, independently read from its canonical SQLite store. A target hold, broker ACK, replay cursor, witness receipt or generic uncertainty hold is a separate observation. If the agent, canonical store or a required native authority is unavailable for more than five seconds after witnessed submission/admission, no algorithm running elsewhere can satisfy that agent-owned unit without changing the acceptance contract. Such a pair remains failed or censored, never removed from the denominator. Merely reducing the KV TTL moves the race to a stale incumbent and provides no cross-broker target fence.

## Proposed protocol, conditional on reviewed contracts

1. **Independent intake.** The signed Revocation 1.1 issuer and grant must bind the exact Finding publisher/UUID/body digest and enrolled local Evidence map. Native T4 must supply complete, challenge-fresh, independently authenticated discovery of every accepted withdrawal since an externally anchored latest floor, even when the coordinator withholds the event. A fresh signed *older* witness head cannot prove completeness. Pin the witness roster/epoch and deny-only admission rule; preserve the 3-of-4 sealed cut for positive history. T5 separately appraises the exact Evidence bundle, claim, material and environment scope through its pinned operators. A Mesh withdrawal need not make T5 report an Evidence withdrawal. Contradiction, expiry, wrong scope or missing required view blocks positive action; only a fully proved withdrawal creates a withdrawal-specific audit row.
2. **Agent-owned denial.** The enrolled agent may run a reviewed deny-only path before broker claim using its canonical audit store. One SQLite transaction must check event ID/body conflict, inventory/policy snapshot and current native proof, then commit `revocation_decisions`, `revoked_targets` and proof provenance. The transaction creates no positive capability and moves neither broker ACK nor authoritative cursor. Its independent rollback anchor must be ahead of any restored store. On an inaccessible agent/store or incomplete Trust view, report a missed/censored agent pair and preserve a restrictive local target state where separately authorized.
3. **Target restriction.** A target-resident path may commit a separate exact-scope deny-only tombstone under the same transaction and monotonic fence as every protected route. The target record binds native proof digest, target identity/generation, plan and Evidence digests, local restrictive capability, current owner floor and earliest expiry. It never clears on lease expiry, expired proof, snapshot restore or unavailable writer. An unreachable target writer is held and cannot acknowledge transfer. A target receipt is scored only in a separate target denominator.
4. **Owner transfer.** An enrolled operator/target authority, not the coordinator or either contender, advances a monotonic generation with an external rollback floor. Its immutable writer roster includes all target routes/replicas and broker ACK/cursor lanes. Two brokers or successors may race; exactly one generation wins. Positive authority begins only after every enrolled writer and lane proves the new floor, old-version credentials are excluded, and an exact fresh local approval plus current native T4/T5 cut is rechecked in the target transaction. Partition, missing receipt, stale snapshot or mixed version leaves positive authority closed. A paused old owner that resumes with a valid old signature is rejected at the final mutation boundary.
5. **Replay and ACK.** The authoritative critical cursor is a compare-and-swap over `(canonical agent store, owner generation, consumer epoch, prior position, event ID/body digest, exact denial commit ID)`. Commit the denial before CAS; send broker ACK only after both. A death before denial leaves cursor unchanged. Death after denial and before CAS replays idempotently. Death after CAS and before ACK may redeliver but cannot add a second logical denial. A lost or delayed old-session ACK cannot change the successor's cursor floor. Restore must compare agent, target and cursor snapshots with independent anchors before any positive recovery.

## Safety argument and open assumptions

The local T3/4E-B home already serializes a fence against a protected target mutation and rejects old signed commands **on that un-restored home**. A retained KV revision and stable UUID are not that home generation. The new tests on this branch show both a one-winner two-contender race and the counterexample: restoring an unanchored target-home SQLite snapshot makes the old assignment current again. They also show that the current `critical_recovery_cursor` has only a position and can be advanced without a denial row. These are reasons to withhold early takeover, not demonstrations that the proposed v2 protocol works.

The safety claim would rely on authenticated, independently administered workload and broker identities; an operator-enrolled complete writer/target roster; at most the reviewed number of faulty T4 witnesses; independently pinned T5 operators; bounded clock error and post-I/O expiry checks; durable atomic SQLite commits; and an external monotonic rollback anchor outside the failed host/snapshot domain. No physical multi-host custody or external anchor is supplied by this local fixture. A malicious coordinator can reorder/suppress transport but must not be able to invent a Trust cut, denial proof, approval or target generation. A revoked or out-of-scope issuer cannot impose a permanent withdrawal-specific tombstone. Native 4E-C remains shadow-only. Every protected route must perform the final target check; no positive route is inferred from a successful health probe alone.
