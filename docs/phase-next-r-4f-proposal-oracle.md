No implementation or shared wire/schema was inspected, adopted or edited. This ruling is frozen before any 4F-R code review and supplements `phase-next-r-acceptance-frozen.md`.

## Agent denial versus target protection

The inherited five-second all-agent unit is **each pre-enrolled agent/withdrawal pair's own committed `revocation_decisions` denial**, read independently from that agent's durable SQLite after its own signature, Trust, inventory and local-policy evaluation. A target-resident sentinel may preserve a restrictive target state before the broker lease clears, but its target-owned `AgentDenialReceipt.v1` is a **proxy receipt**, even if it carries that agent's UUID and a target-home signature. It does not prove that a killed or partitioned agent received, evaluated or committed the withdrawal. It cannot enter the numerator of the frozen 72 fault pairs or 18 controls. A generic uncertainty hold, broker ACK, cursor or witness receipt also cannot count. Record proxy receipts and restrictive target state as separate target-protection metrics, with their own target count and independently read transaction/fence proof.

Negative control: pre-enroll three agents, kill or partition two before intake, and let the sentinel commit three target-home per-agent receipts. The two absent agent-owned audit rows remain **two missing/failing agent-pair observations**, not 3/3 delivery coverage. A later agent-owned denial after restart is timed from the original witnessed submission **and** durable admission. If the retained 30-second lease blocks that row, the five-second agent gate fails regardless of a timely target hold. Changing this metric would require an explicit reviewed acceptance-contract version and re-baseline; this proposal does not provide one. The target sentinel is still a potentially valuable *separate* protection path if it has an exact locally enrolled deny-only capability, independent native status proof, target-side transaction and safe rollback anchor.

## Trust, outage and authority challenge

The proposed `WithdrawalAcceptance.v1` combines one exact, scoped and valid witness-admitted withdrawal, all four fresh authenticated withdrawal views, current T5 exact Evidence status, and a 3-of-4 sealed T4 cut where required. Separate these states in raw results: witnessed intake, sealed inclusion, current positive status, proven withdrawal-specific denial and unknown/contradictory hold. A witness receipt alone is not a current T4/T5 cut or arbitrary denial license. A forged or out-of-scope issuer, fabricated one-witness receipt, wrong finding/Evidence digest, stale checkpoint, revoked key or expired proof must not create a verified-withdrawal tombstone. Missing or conflicting current views block new positive authority, but may create only a policy-authorized, separately labeled uncertainty hold.

With one of the four required withdrawal-view authorities unavailable, the 3-of-4 history cut may still be verifiable under its stated fault model, while the proposed all-four fresh-view rule cannot establish a current positive appraisal. That is a safe availability failure. It also cannot be counted as an on-time specific withdrawal denial without the proposal's exact current proof; any affected agent pair remains missed/censored and keeps the five-second release gate **NO-GO**. Test delayed acceptance after the final status read, one withheld but valid withdrawal, conflicting checkpoints, and direct independent discovery when Mesh/coordinator suppresses delivery. All authority reads need a post-I/O freshness check; a nonce or old signed status does not extend expiry.

## Recovery, backlog and denominator

The freeze requires **1,000 ordinary pending findings per fault run**; the proposal's conditional “add if required” is resolved as mandatory. Keep smaller four/six-row diagnostic comparators separately. The exact local matrix is 3 agents × 2 withdrawals × 3 fresh repeats × 4 arms = **72 agent-owned denial pairs**, plus 18 healthy controls. Require both witnessed submission-to-agent-denial and witnessed durable-admission-to-agent-denial conservative upper bounds ≤5,000 ms for every eligible pair; do not subtract SIGKILL, partition or broker outage. Target sentinel receipt and target hold have separate latency and coverage denominators. Record each agent's ACK/cursor generation and each target's fence; stale old-session ACK cannot advance the successor floor, and old signed commands cannot cross the target mutation boundary. Do not reopen a known vulnerable route after snapshot restore, lease expiry or incomplete all-writer barrier.

Local containers can challenge state-machine logic but cannot establish independently administered multi-host identity, witness custody, rollback-resistant anchor or every physical writer. No enrolled external hosts or credentials are supplied. Those release gates remain unobservable and **NO-GO**. The proposal is **REVISE for metric compatibility and proof semantics**, while the current fail-closed implementation and original failure evidence remain authoritative. No production or distributed autonomous enforcement follows.
