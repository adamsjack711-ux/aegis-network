## Proposed dependency-provisioning gate

1. A separately authorized custodian acquires **original upstream archives** and matching image digests outside the release test. This proposal authorizes no download or image pull. Record upstream identity, acquisition time and channel, supplier signature or index metadata where available, original SHA-256, license, exact version, wheel tags and the independent review commit for every build and transitive runtime archive.
2. An independent reviewer checks the original Hatchling archive and build dependencies, cryptography and pydantic-core wheels for each Python/platform tag, all other resolved dependencies, and the source distribution. Reject an extracted cache, renamed archive, borrowed Debian wheel for Ubuntu without compatibility proof, or a caller-authored provenance label as supplier authentication.
3. Seal a read-only local wheelhouse and manifest, then pass only its path and hashes to a disposable non-root builder. Build the same exact Git source twice offline under a fixed `SOURCE_DATE_EPOCH`; compare wheel and sdist byte hashes, metadata, generated `aegis` entry point and 68 source package files. A missing archive stops the gate before installation.
4. In pinned Debian 13/Ubuntu 24.04 × Python 3.12/3.13 images, use `--network none` and `--pull never`; install with normal `pip --no-index` dependency resolution into empty venvs, compare installed archive hashes with the reviewed manifest, and run the frozen console, tracing, resource, uninstall and non-root checks. Preserve a per-cell raw result and explicit skip reason. A failed cell cannot be substituted by a source-only diagnostic.
