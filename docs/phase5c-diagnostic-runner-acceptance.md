# Phase 5C independent test and acceptance plan

**Status:** proposed pre-implementation gate. No Diagnostic Runner exists at the design pin. The test owner must freeze fixtures and oracles before reviewing implementation, run against an exact clean source and package pin, and publish raw failures as well as a summary. Source-level parser tests cannot establish installed Linux sandbox behavior. The existing Phase 5B installable-alpha and 256 MiB/100,000-row gaps remain separate open gates.

## Reproducibility and authority checks

For every run record source commit, clean/dirty tree, registry digest, schema revision, wheel/sdist hash, image digest, Debian/Ubuntu release, Python version, systemd/kernel/cgroup mode, UID, unit settings actually applied, network namespace identity, CPU and memory caps, command argv, fixture hash, monotonic and wall timing, and raw exit/result/audit records. Use offline pinned disposable containers or VMs with no external targets, package refresh, model endpoint or production credentials. The independent reviewer owns negative fixtures and a separate observation oracle. Report planned, attempted, completed, failed, skipped and inconclusive counts; an unavailable cgroup controller, user manager or syscall tracer is an explicit inconclusive gate, not a pass.

Before any implementation acceptance, inspect the diff from `ec939e1`: original `src/aegis/artifact.py`, `core.py`, `trust.py`, native T4/T5, Rapid approval, protected writers and Phase 5B default CLI behavior must be byte/behavior compatible. Run existing focused CLI and Rapid/Trust regression suites at the candidate pin. Confirm no diagnostic schema is accepted by existing signed-event readers. No test result here grants production distribution or privileged enforcement.

## Security and resource trials

Run each operation under an ordinary UID on pinned Debian and Ubuntu with a real installed one-shot service. Trace `execve`, `connect`, file opens/writes, privilege/capability changes, namespace and cgroup membership. Compare to an independently declared allowlist. Confirm zero shell invocation, dynamic executable selection, outbound connect, privileged file access, service mutation, package mutation, target writer import/call and unaudited state path. A systemd directive being present in a unit file is not evidence that it took effect; inspect the effective unit and process/cgroup state. A missing tracer or denied sandbox feature makes the relevant hardening claim inconclusive. Use a fixed local D-Bus fake or disposable service only; no production service changes.

For each operation and three input scales (minimal, normal, worst accepted), run **three fresh trials** plus three malformed/oversized trials. Proposed ceiling per run: package 3 s wall/2 s CPU/128 MiB; service and ports 2 s wall/1 s CPU/64 MiB. Capture actual worker-group peak memory, CPU, elapsed, process count, stdout/stderr byte count, result bytes, kill/reap time and cgroup OOM events. Simulate slow output consumer, blocked bus, infinite parser input, child fork and cancellation. One over-ceiling run fails that operation's envelope; there is no retry that erases the failure. Limit canonical result to 4 KiB (2 KiB service) and input table reads to registry constants that independent fixtures prove adequate. A resource failure yields a bounded non-complete result and no lingering child.

The group limit is essential if a subprocess can fork. `RLIMIT_AS` and `RLIMIT_CPU` are supplemental per-process limits; validate the actual cgroup memory/CPU limits and whole-group termination. Test operation-specific sandbox access: package status read succeeds, service status can reach only the approved local manager interface, ports see the intended current namespace. A port sandbox that sees an empty private namespace must fail the correctness gate, even if it is more isolated. Check offline boot, execution, review, revoke and uninstall with network disabled; an unavailable remote adapter cannot cause execution or sharing.

## Release verdict and handoff evidence

An independent **GO for a restricted local alpha** requires every functional/security case above to pass at the exact installed pin, all supported OS rows to be complete, all three operations within the measured resource envelope, zero forbidden attempted effects, stable private schemas and the original CLI/Rapid/Trust regression. A skip or inconclusive required row is **NO-GO for that claimed capability**. A local source-only prototype may be reported separately but is not an installable-alpha result. Keep remote-result sharing disabled until a separate destination/consent schema and negative tests are approved. A future standing remote rule, privileged daemon, new operation, broader distro or shared authority interface needs a new freeze and review.

The validator's handoff must include exact source and harness commits, test commands, environment and fixture digests, raw structured results/traces, per-case denominator and failure list, the first failure retained if later retries pass, measured p50/p95/p99/max with all over-budget cases, and an explicit scope-limited verdict. The implementation owner must document install, opt-in enable, revoke, export and uninstall procedures, plus recovery from corrupt state. The architecture branch's own evidence is limited to documentation consistency and Git diff checks; no runtime acceptance is claimed.
