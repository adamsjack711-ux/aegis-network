This document changes no code, signed bytes, local approval, native T4/T5 status, or protected writer. No diagnostic execution, external connection, production target or model call was performed. Phase 5C is an explicitly invoked, observation-only local-lab capability. Its output is a lead for a human and independent verifier, never an authority input by itself. ## Why a separate runner

The current Linux CLI reads local dpkg state and signed Mesh files offline. The Evidence `runner.run` invokes one digest-pinned, stdlib-only worker for registered inert marker fixtures, with bounded input, a subprocess timeout, resource limits and a Python audit hook. That worker is not a general-purpose sandbox. Phase 5C must not broaden its accepted vocabulary or let a coordinator/advisory/model supply an executable recipe. A new private Diagnostic Runner may reuse the *pattern* of exact code/data pins and independent controls, but any probe beyond the existing fixed fixture requires OS-level containment review and an independent acceptance gate.

## Plane and trust boundaries

```text
administrator-owned local enrollment and operator-minted one-use session capability (outside request JSON)
  → broker verifies peer principal; launcher verifies capability, profile and fixture scope
  → launcher seals selected input bytes and worker rechecks their digest
  → disposable restricted worker with pinned image and containment profile
  → bounded parser and control checks
  → provisional DiagnosticObservation to stdout
  → optional explicit operator capture and independent review

research/advisory/CLI suggestion ──> profile identifier only; no execution authority
Mesh/T4/T5/Rapid/protected writer  <── no direct input from DiagnosticObservation
```

The operator chooses the local target and profile for **one** run through a trusted local authorization broker and launcher. A JSON field cannot assert operator approval. A local administrator controls a root-owned enrollment registry. The broker checks Linux peer credentials on a private Unix socket and, only for an explicit local operator invocation, mints an unexported one-use session handle bound to enrollment, profile, run ID and short deadline. The launcher seals the selected input snapshot; the broker then binds the handle to its digest and consumes it atomically before launch. A changed or replayed digest requires a new operator invocation. The capability is a connection/descriptor handle, **not** a bearer value in an artifact, model response, request JSON or log. A copied request lacks the active capability. The launcher opens its installed executable and registry through pinned descriptors and verifies their reviewed digests; an operator-supplied path or mutable tag cannot select code. Enrollment creation, expiry and revocation belong to a separately reviewed local administrator procedure. Same-UID caller impersonation, broker compromise and concrete host permissions require VAL-1 review before implementation intake.

There is no scheduler, remote profile loader, public scan, crawler, arbitrary host or network address, generic shell, injected script, or automatic retry. The local broker is an authorization component, not a subscriber or autonomous scheduler. No command line is taken from an artifact. A coordinator can at most provide untrusted context displayed as data; it cannot enroll a target or select a new executable. The launcher resolves a bounded fixture file relative to a preopened enrolled root, rejects symlink/device/traversal and concurrent replacement, checks source descriptor identity and metadata before and after copying exact bytes into a private sealing-capable memory descriptor, seals write/grow/shrink/further seal changes, then hashes the sealed bytes. The worker receives **only that descriptor**, verifies the seals and digest before parsing and never reopens a mutable host path. An immutable snapshot is therefore an output of preflight, not an assumption about a read-only mount. An optional future live local probe needs a separate target-enrollment and side-effect review; this proposal does not authorize one.

## Safety and audit path

Preflight fails closed before launch if the target is not an authorized disposable fixture, the one-use capability or enrollment is absent/stale/revoked, the sealed input digest differs, the profile is absent/changed, a resource ceiling is exceeded, or a path escapes its pinned root. A failed control, timeout, signal, partial output, parser error, policy ambiguity or missing source becomes `inconclusive` or `rejected`; neither absence nor a nonzero process exit means the target is safe. Only a locally installed allowlisted worker is executable. The launcher may start that pinned worker; the worker cannot exec a second program or open a socket. The watchdog kills and reaps the entire worker cgroup on timeout, cancellation and abnormal exit, then independently reads back cgroup/process and disposable-mount cleanup.

The default command writes **no persistent host state**. It streams a bounded result and sanitized per-run transcript to stdout with literal `independent_status="unknown"`. An optional output file requires a separate **operator-minted output capability**: a preopened private directory descriptor and exact leaf identity, bound to the run and consumed once. Arbitrary JSON paths are ignored. Descriptor-relative creation under the preopened directory uses exclusive, no-follow creation and rejects ancestor/final symlinks and concurrent replacement; only the granted file may be created. A separate lab audit collector may hash and retain the transcript, but a local hash is bookkeeping, not independent custody or a signature. The result records source/profile/input digests, controls, result, reason, resource use and clock method so an independent reviewer can reproduce it. Never include credentials, tokens, arbitrary environment variables, full package databases or private user files. Disposal of the worker and tmpfs is mandatory after every outcome, including cancellation.

No automatic bridge exists from a DiagnosticObservation to `SignedFinding 1.0`, native Evidence, T4/T5 status, Rapid local approval, mitigation templates or protected writers. A future evidence adapter would need a versioned proposal, independent verifier organizations, registered environment/check/oracle pins, negative semantic tests, old/new reader compatibility, and explicit integration approval. A valid worker signature or digest alone would not prove the claim true. The current 4F five-second all-agent withdrawal gate and distributed-enforcement NO-GO remain unchanged.
