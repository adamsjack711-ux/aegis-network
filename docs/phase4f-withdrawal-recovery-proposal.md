# Phase 4F withdrawal recovery: diagnostic proposal

Branch `feat/phase4f-withdrawal-recovery`, starting at `192feacf0c015c1fa37b075228b258d70e565d42`. This is a design-only proposal. Independent validator freeze `2eb2ca27be986f3b55e3f85c2067ae6672d213a5` and its `docs/phase-next-remediation-validation-freeze.md` control closure. Native T4/T5 authority, the inherited five-second all-agent withdrawal ceiling, and all original failure artifacts remain unchanged. Distributed enforcement stays disabled.

## Retained observation and causal question

The independent exact-`51e5601` pre-intake SIGKILL plus broker-restart trials report first durable denial 30.610 and 30.710 seconds after submission, or 30.539 and 30.639 seconds after the restart request. The same one-agent trials eventually record both denials, eight logical ACKs, and priority withdrawal progress with six ordinary outbox rows pending. These are readbacks of dry-run SQLite, not target holds or multi-host proof. Retain `benchmarks/phase-next-validation/native-4f-preintake-priority{,-repeat}.json`, `docs/phase-next-validation.md`, and the Phase 4E predecessor traces verbatim.

The approximately 30-second interval **suggests**, but does not prove, a broker identity lease wait. `agent_runtime.run()` claims the stable identity before creating critical wire or replay tasks (`src/aegis/agent_runtime.py`); `IdentityLease.claim()` retries KV `create()` at one-second intervals for up to 45 seconds, while the broker FILE KV lease TTL is 30 seconds (`src/aegis/identity.py`). SIGKILL does not call `release()`. The existing harness samples submission, restart request, SQLite commit and ACK, but lacks timestamps for broker readiness, agent process start, KV claim attempts/success, replay start and independent publication. Broker startup, KV expiry, client reconnect, HTTP replay and scheduling remain unexcluded causes. Do not change the TTL, forcibly delete a lease, or let critical intake bypass identity based on this correlation.

## Instrumentation and isolation order

1. Use the independent validator's frozen two raw failures and harness pin (SHA-256 `5e9be722264b46b54b606f38d9d77ef0355b600a292baadd471e260771a27a18`). Run the same fault unchanged at a new exact candidate pin before interpreting an instrumented rerun. Preserve both raw SHA-256s and all Phase 4E failure XML.
2. Add structured, non-secret correlation IDs to a **diagnostic harness** and local actor logs. On one host, use one `monotonic_ns` clock in the controller for submit, independently witnessed acceptance, broker stop/start request, broker ready, child spawn/ready, read-only SQLite denial observation and ACK-floor observation. Export process-local `perf_counter_ns` spans separately and pair them with controller-observed milestones; do not subtract unrelated process clocks. Record each agent ID, lease generation/revision, critical consumer name, signed event ID, journal position and retry reason. Never log tokens or signed payloads.
3. At the identity boundary, timestamp each KV claim attempt and result, preserved key revision/expiry if the broker API exposes them, and the first successful fenced ownership generation. At delivery, timestamp critical subscription, first fetch, signed-event verification, local SQLite commit, replay-cursor commit, `ack_sync` attempt and broker-confirmed ACK. At coordinator, record PostgreSQL acceptance, outbox eligibility, critical publish attempt and confirmed JetStream sequence. For native protection, separately measure T4 inclusion/T5 withdrawal status, protected writer denial and independent target hold.
4. Partition the interval using controlled one-factor trials: SIGKILL without broker restart; broker restart without SIGKILL; graceful release versus SIGKILL; normal versus retained prior lease; no ordinary load versus bounded ordinary burst; wire delivery versus journal replay; lost ACK after SQLite commit. Repeat each with fresh disposable state. A roughly 30-second claim interval plus prompt downstream spans would support the KV hypothesis; a prompt claim with delayed broker/outbox/consumer/replay stages would falsify it.
5. Only after the measured blocker is localized, propose a versioned owner-transfer protocol. Early recovery may occur only with authenticated successor identity, a durable monotonic generation committed in a failure-independent authority, proof that every enrolled protected writer and relevant ACK/cursor lane rejects the prior generation, a current native T4/T5 cut, and exact local approval for any new protected write. A broker lease alone cannot prove the old agent is fenced on another broker or host. If these barriers cannot be established, retain the wait and deny new authority; a five-second recovery claim is then unavailable for that fault model.

## Falsifiable five-second acceptance

Pin one exact integrated commit and publish the full enrolled-agent roster **before** injection. Define `t0` as independently witnessed, durable acceptance of a valid signed in-scope withdrawal; also report submission-to-denial for comparison with retained failures. For each enrolled agent, measure the first independent read-only observation of its committed local denial, with polling interval and lower/upper bound, plus any target hold separately. Record broker delivery, replay, cursor, and ACK as distinct milestones; none substitutes for denial or grants authority. The denominator is all enrolled agents, with connected, crashed, partitioned and unreachable actors shown individually. Missing denial or missing proof is a failure/inconclusive observation, never silently omitted. The all-agent gate passes only if **every eligible connected agent's conservative upper bound is at most 5.000 seconds**, with the pre-intake crash and broker restart arms reported separately and passing their declared recovery policy. Do not relax the inherited ceiling to p95.

The frozen minimum closure oracle is **three entire fresh-state repetitions** of pre-intake SIGKILL plus broker restart, with ordinary findings queued and at least two withdrawals: an independent revoker and a mixed publisher-sequence withdrawal. Include a healthy no-fault control, duplicate/lost ACK and replay, stale owner and network partition. Declare enrolled agents, targeted agent-withdrawal pairs, admitted events, eligibility after connectivity restoration and censored pairs **before** running. For every eligible pair report both submission-to-denial and restored-connectivity-to-denial; require all eligible pairs to have durable denial within 5,000 ms under the declared origin, zero unauthorized positive writes and zero omitted agents. If connectivity remains absent, record and censor the isolation interval explicitly. A pre-intake crash cannot invent admission. A new one-agent pass does not erase the original gate failure. Do not substitute outbox publication, ACK, cursor or native target hold for denial or independently verified Trust.

After the frozen minimum, extend to 3, 10 and 100 simulated agents where resources permit, with saturated ordinary stream, competing owner, stale/copy-restored cursor, delayed/suppressed withdrawal, expired Evidence and T4/T5 unavailable or contradictory status. Require no duplicate logical denial, no cursor advance before durable decision, preserved denial after restart/snapshot restore, and restrictive target state throughout. Report raw per-agent times, all-agent maximum and p50/p95/p99, CPU/RSS, broker backlog, repeat count and failures. Physical multi-host, independent custody and rollback anchors remain separate open gates.

## File ownership and review boundary

This branch owns this proposal and, after validator freeze and interface review, only withdrawal recovery diagnostics/tests in `scripts/phase4e_withdrawal_recovery_check.py`, a new diagnostic harness under `scripts/`, and new tests under `tests/phase4e/`. Potential product changes to `src/aegis/identity.py`, `agent_runtime.py`, `recovery.py` or `storage.py` require a field-level versioned contract proposal and integration review because they touch identity, ACK and cursor semantics. The native mitigation/store and T4/T5 authority modules belong to their existing owners; this branch will not edit them. No implementation files are changed by this proposal.
