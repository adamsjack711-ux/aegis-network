## Contract review and decisions

The authoritative `SignedFinding`/`Finding.schema_version="1.0"` canonical bytes, `InventoryItem(purl, version)` exact matcher, native T4/T5 status, and revocation/denial rules are unchanged. Phase 4F edits only the native disposable target store and fixture lifecycle, plus tests and retained data. Its branch-local test migration expects a stronger durable quarantine before the first observer. The original two-failure JUnit and predecessor reproduction are retained. The target remains single-use after a safe hold; positive native reopening requires a separate versioned authorization contract. Generation-bound JetStream ACK/cursor fencing is still a proposal, not integrated code.

Phase 5A's committed `SourceSnapshot`, `Claim`, `Asset`, `Assessment`, and `ResearchResult` are private provisional records; the field gap against proposed `AdvisoryInput.v1`/`ResearchCandidate.v1`/`ResearchCheck.v1`/`ResearchReview.v1` is documented in its branch report. Its local fixture CLI and `FeedClient.fetch` reject external retrieval. An independent scripted test demonstrated that a valid citation ID can accompany unsupported affected-version and remote-execution prose. The returned record said `independently_verified=false` and could not become a signed finding, but the research-output guardrail failed. The proposed disposition is to keep model prose an unverified hypothesis and require an explicit inconclusive/needs-evidence check whenever the model advances beyond deterministic support; every freeform factual point still needs claim-level review. This is a **proposal**, not an adopted shared contract.

Phase 5B adapts signed Mesh Finding 1.0 and local exact Debian package/version matching without modifying signature semantics. Its private `inventory-v1` and `observation-results-v1` outputs are not adopted shared schemas. Independent testing found two intake conflicts: ordinary commands create a persistent local UUID file without explicit storage opt-in, including on failure paths; and a signed claim can be labeled `current` and exact package `matched` while current independent Evidence/T4/T5 status has no structured field. The private CLI must keep package match, signed claim validity, and independent status distinct; unknown independent status must remain explicit. No 5A research candidate to 5B observation adapter is approved.

## Remaining gates and release decision

- **Phase 4F native local lab candidate: GO for further isolated integration testing.** Independent pre-observation hold evidence and the integrated regression suite pass. Generation-bound broker ACK/cursor fencing, positive native recovery, target process SIGKILL supervision, physical multi-host custody and rollback anchors remain open. The independent pre-intake SIGKILL/broker-restart repetition **missed** the five-second all-agent withdrawal gate by about 25.6 seconds. Distributed write authority remains disabled.
- **Phase 5A read-only research experiments: GO; release or cross-system adapter: NO-GO.** Resolve the unsupported positive-prose failure, then rerun the independent holdout and guardrails. Do not treat scripted fixture scores as model benefit or research text as verified Evidence.
- **Phase 5B observation CLI design: GO; installable alpha integration: NO-GO.** Resolve default writes and structured independent status, then repeat signed/unknown/partial controls and offline non-root wheel installation on declared Debian and Ubuntu images. The currently committed CLI does not enter this integration branch.
- **Distributed autonomous enforcement and production deployment: NO-GO.** Native T4/T5 stays authoritative; no external hosts or real credentials were used. Master was not merged.

The next intake order is a reviewed Phase 4F ACK/cursor protocol with independent fault tests, then a 5A private research-result guardrail correction, then a 5B default-ephemeral identity and status-output correction. Each completed exact pin requires its own focused, full and cross-component tests before a further integration merge.
