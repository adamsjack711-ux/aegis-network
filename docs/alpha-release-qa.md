# Alpha Linux CLI release QA — 2026-11-20

## Scope, pins, and recommendation

**Recommendation: NO-GO for an installable Debian/Ubuntu alpha and for a 256 MiB Linux resource claim.** Source-level observation behavior passes the focused checks below, but the current integrated commit has no completed offline build or four-cell installed acceptance run in this environment. The known grant-file check/read race remains an expected failure. No application implementation or frozen acceptance criterion was changed in this QA branch.

Tested integration source: `0fd24dbf31a1fcc5acb17495004800dbc5ad3b61` (`integration/alpha-readiness-astra`). Later commits through `0fd24db` include other integration and QA work; the present QA tests the full tree at `0fd24db`, not those commits individually. The main checkout was dirty and was neither edited nor used for test results. This worktree was created from the integration ref on `docs/alpha-release-qa`.

The governing installed-alpha criteria are [Phase 5B-A acceptance](phase5b-alpha-acceptance.md) and the [independent Alpha Readiness freeze](alpha-readiness-validation-freeze.md). They require two byte-identical offline wheel/sdist builds; four fresh Debian/Ubuntu × Python 3.12/3.13 installed cells; 84 installed logical CLI cases; 68 resource/privacy children; attempted-effect syscall evidence; and 100,000-row wall and CPU ≤5 seconds, RSS ≤256 MiB, complete output, and three hard-256 MiB completions per cell. Source tests and a host diagnostic do not replace these denominators.

## Resource and evidence assessment

The new macOS source diagnostics both fall below 256 MiB and five seconds, with complete local output for the 100,000-row inventory. They carry no hard 256 MiB memory limit, Linux runtime, installed wheel, or three-run distribution denominator. The retained earlier installed Debian 3.12 baseline measured about **297.805 MiB** peak RSS at 512 MiB and **3/3 OOM kills** at 256 MiB for 100,000 rows. A later streaming serializer candidate `9b69c486b1dd6dff1d7eaa0f7a3858c711385d41` completed **3/3** source-only Kali/Debian-identity fixture trials under a 256 MiB cgroup at about **107.219 MiB** peak RSS; that was not a real Debian/Ubuntu installed cell. See the [independent serializer review](phase-next-r-5b-independent-review.md). These observations must remain separated by pin, runtime and harness. **The documented 256 MiB Linux installed limit is not demonstrated for the tested integration pin.**

The source suite's xfail is a known size check/use race in the local publisher grant path. [Independent grant review](alpha-readiness-validation-grant-proposal.md) retained a `--runxfail` reproduction (`Failed: DID NOT RAISE ObservationError`) and requires a single bounded descriptor read with compatible grant semantics. That is a CLI input-bound defect; the cited evidence does not establish a publisher-authorization or signature bypass. This QA work did not run the adversarial reproduction.

## Outstanding release requirements

2. Supply an independently reviewed, locked local wheelhouse with the actual Hatchling and runtime archives. Produce two byte-identical offline wheel and source distributions from the same exact source, inspect generated entry point and dependencies, and retain archive hashes.
3. On that same pin, run fresh non-root Debian and Ubuntu installs with Python 3.12 and 3.13 using each distribution's own dependencies. Exercise the generated `aegis` executable and direct uninstall/cleanup in all four cells.
4. Complete the frozen **84** installed logical CLI cases and **68** resource/privacy children, including all five commands, malformed/unknown/signed inputs, explicit-state controls, no unrequested writes, and attempted-effect syscall observation. Retain per-cell raw exits, output, filesystem snapshots, image/wheel digests and skip reasons.
5. Run three fresh hard-256 MiB 100,000-row children in every cell, with complete identity-checked output, ≤5 s wall and CPU, ≤256 MiB process RSS, zero OOM and the declared output bound. Keep the historical OOM result visible; a changed limit would need a versioned acceptance decision.
6. Rerun the broad regression where local socket fixtures are permitted and classify each remaining failure. The sandbox-denied run above cannot certify the integrated release.
