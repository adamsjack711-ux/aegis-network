## Contract questions to settle before code

1. **Exact open/read linearization.** Specify the trusted root descriptor, per-component `O_DIRECTORY|O_NOFOLLOW`, macOS root-owned `/var`/`/tmp` alias rule, final `O_RDONLY|O_CLOEXEC|O_NOFOLLOW|O_NONBLOCK`, regular-file `fstat`, maximum 1,048,576+1 bytes, post-read size/identity checks and exact closed-FD error behavior. If no-follow or descriptor walk is unavailable, reject. A path swap after open must never switch the parsed inode. A same-inode rewrite during read can produce mixed bytes even with one descriptor; specify the local operator file custody assumption and a conservative concurrent-mutation check. Do not claim the reader provides an independently witnessed latest revocation floor.
2. **Mode and owner compatibility.** Baseline parser does not enforce file mode. Decide explicitly whether `0600` and `0644` are both valid for current-UID and root-owned operator files, whether group/other writable modes are newly denied, and how ACLs, owner/group changes and root aliases are handled on Linux/macOS. Any tighter rule is a versioned input compatibility decision, not a silent parser cleanup. The concurrent validator's additional 12 grant race/permission cases are supplemental until this policy is frozen.
3. **Old/new semantic vectors.** Retain byte-identical SignedFinding 1.0 and Revocation 1.1 fixtures across legacy map, valid grant list, finding versus revocation role, scoped `revocation_publishers`, not-before/expiry/revoked boundaries, key rotation/overlap, duplicate/conflicting entries, wrong key or publisher, malformed/oversize and unexpected fields. Compare the old `Path.read_text()` UTF-8/JSON behavior with new bytes parsing for BOM, duplicate JSON keys and alternate encodings; any intentional rejection tightening needs review. Assert identical `TrustStore` authorization outcomes and zero finding/status/policy promotion, with no default write.
