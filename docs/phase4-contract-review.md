# Phase 4 shared contract freeze

## Baseline and decision

Freeze the contracts at Phase 3C commit `7744ebd7f80e6f2aabb253d5cc3ec9972c86cffd`. The freeze applies to observable behavior and security invariants as well as wire fields. Keep new interfaces branch-local until reviewed. The Phase 2 contracts describe the existing Mesh wire. The Phase 3C handoff describes the local Evidence and mitigation boundaries added above it. Source and tests at the pinned commit are the compatibility reference when historical prose differs. [Phase 2 contracts](contracts.md) · [Phase 3C integration](phase3c-integration.md)

Approval and target capabilities stay local. | Integration lead and 4C, with 4A/4B for affected inputs |
| Target and observer | `mitigation/store.py` and `mitigation/observer.py`. Preserve the fenced conditional write and audit commit, one target per capability, canary before peers, evidence and approval deadlines, and independent marker and benign checks for every declared path and replica. Missing evidence, stale scope or failed recovery cannot be recorded as confirmed. Preserve verified quarantine on loss of status or health after leasing. Local Python methods and SQLite layouts can evolve behind compatible adapters. Any change to persistent semantics, migrations, audit attribution, freshness budgets or authorization timing still requires review. Unapproved readers cannot infer current authority from historical rows. Treat private approval material and recipient inventory as local. Existing numerical retention and timeout defaults are control settings. Changes need a reason, a before/after check, and approval from the relevant owners.

## Review queue

| Proposal | Disposition for exploration | Required review evidence |
| --- | --- | --- |
| Separate broker credentials, transport process separation, or network instrumentation | 4A may prototype behind the frozen reader and writer contracts. | Old and new agents can operate under the declared topology. Test the denial of impersonated identities and the handling of lost acknowledgment, reconnect, and expiry. Record whether trust differences affect comparability. |
| Portable Evidence serialization or a new compatibility rule | 4B may build a separate experimental package and compatibility matrix. Current signed manifest and attestation bytes stay intact. | Test consuming existing packages, strict parsing of new data, exact versus compatible versus unsupported cases, keying, cohort isolation, and reappraisal after all invalidation sources. Distinguish portable provenance from evidence newly verified on a different subject. |
| Independent status witness or authenticated replay | 4C may specify a protocol and run local simulations with 4A. Adding a field to the old signature or treating a self-reported head as a witness requires a new compatibility decision. | Bind the threat assumptions, freshness and quorum, monotonic state and recovery after partition or restore. Prove that withheld or inconsistent status cannot authorize a new mutation, and that a healthy view still progresses. |
| New remote capability format or broader lab action | Outside the frozen action boundary for this cycle. | Requires a separately scoped architecture and authorization decision, a migration and recovery design, and a review of who has target write authority. |

## Change review procedure

1. Open a numbered proposal with owner, exact changed surface, failure behavior, data classification, and compatibility and threat impact. Include concrete old/new bytes or examples when relevant.
2. Attach golden vectors, a reader/writer version matrix, tested persistence and rollback behavior, and a fault matrix. Compare old and new active decision outcomes and preservation of previous denials. Any downgrade must retain the strongest known denial or hold.
3. The surface owners and 4C reviewer give a recorded recommendation. The integration lead approves or declines the change in an ADR. Use a separate protocol version and explicit opt-in when compatibility cannot be proved. Readers deny unsupported data.
4. Integrate only after an approved test plan and exact commit review. Add the smallest compatible change to the candidate and rerun the applicable checks before the next integration step. Update the associated contract description only when the phase adoption decision is recorded.

The Phase 4 review approves this freeze and bounded experiments. No interface proposal in the queue is adopted. The current wire contracts in the repository are unchanged.
