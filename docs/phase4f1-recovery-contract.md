## Frozen authority and fault assumptions

- Native T4 is the Mesh history authority: four operator-pinned witnesses, native policy context, at most one faulty witness, and a **3-of-4 sealed cut for positive authority**. Native T5 is separately administered Evidence status with two pinned status witnesses. 4E-C `WithdrawalView` and `/v2/withdrawals` are shadow data and never an authority source. A broker ACK, replay cursor, target sentinel, coordinator assertion or model output grants no authority.
- The proposed *specific, deny-only local audit* may use one native witness's durable acceptance of a **valid, scoped, publisher-signed Revocation 1.1** before a 3-of-4 cut, but only with independently retrievable current obligation proof and pinned historical/current grant rules. This cannot authorize a target mutation, ownership transfer, positive plan or ACK/cursor movement. An Evidence withdrawal without that Mesh revocation creates a separate Evidence hold, not a Mesh `revocation_decisions` row.
- The proposal introduces an independently administered admission-anchor authority. Its signing key, workload access, durable monotonic floor and rollback domain must be operator pinned **outside** the witness, agent, broker, coordinator and restorable target snapshots. The narrow fault model assumes this anchor is honest and reachable for a specific verified denial, while allowing one faulty T4 witness. An unavailable, equivocal, compromised or stale anchor gives `unknown` and a restrictive hold, not a scored denial. One independently administered anchor is an availability dependency and does not by itself prove Byzantine tolerance. A stronger replicated-anchor policy needs a separate protocol review.
- An offline agent, inaccessible canonical audit store or missing required T5 view cannot commit an on-time agent-owned denial. No protocol can meet the frozen all-agent deadline for an agent that remains killed or partitioned for more than five seconds. Those arms remain missed/censored; a target hold has its own denominator.

## Proposed native T4 admission and current-floor protocol

This is a **new native T4 versioned contract**, not the current `/v1/journal` API. Existing `Witness.admit` validates and persists a known event, and `HTTPWitness.admitted(event, epoch)` retrieves it by coordinates; neither permits discovery of a suppressed unknown event. The sealed archive can lag accepted obligations. The proposed native endpoint and record domains require independent Main/VAL-1 review and interoperable golden vectors before any runtime intake.

| Record | Required strict fields and binding |
| --- | --- |
| `NativeObligation.v1` | T4 context and policy/roster digest, witness operator/key and signature, admission epoch, strictly increasing witness obligation ordinal, original canonical **signed Revocation 1.1 envelope bytes**, event digest, revoker grant/key digest and authorized target-publisher scope, original target triple, validation time interval/error, prior obligation root and new root. Same event ID with different bytes or publisher sequence conflicts. |
| `NativeAnchorAcceptance.v1` | Anchor ID/key/context, obligation witness/ordinal/root, exact source-wire/event/grant digests, anchor global ordinal/root, previous root, durable commit UTC interval, expiry and a domain-separated Ed25519 signature. The anchor independently verifies witness signature, signed revoker scope and T4 context, then durably stores the **source bytes**, not just a digest. |
| `NativeFloorChallenge.v1` | Enrolled agent/store/workload identity, T4 context, previously pinned anchor `(size,root)`, fresh 32-byte nonce, UTC interval with clock error, requested page size 1–128 and bounded response budget. Authenticated directly to the pinned anchor; no coordinator-provided event ID. |
| `NativeLatestFloor.v1` | Challenge hash, anchor/global `(size,root)`, signed issue/expiry, per-witness latest **accepted** obligation `(ordinal,root)`, anchor consistency proof from prior floor and terminal page commitment. This floor is read directly **after** the independently witnessed submission/admission under test and before accepting a witness view. A fresh signature over an old root fails if below the anchor's current floor. |
| `NativeObligationPage.v1` | Anchor head/root/nonce, contiguous 1–128 ordinals, original source bytes, witness and anchor acceptance records, inclusion/consistency proofs, next position, and a signed terminal position exactly equal to the pinned head size. Every page is bound to one immutable head. Dense traversal from prior floor through terminal discovers all eligible withdrawals regardless of coordinator/broker suppression or a 1,000 ordinary-finding backlog. |

Proposed encoding is strict `journal.protocol.canonical` UTF-8 JSON for the new native bodies and signed envelope, with duplicate keys/unknown fields/alternate encodings rejected. The existing Ed25519 library signs distinct `aegis-native-t4-obligation/v1\x00`, `aegis-native-t4-anchor/v1\x00` and `aegis-native-t4-floor/v1\x00` domains followed by exact canonical body bytes. Do not reuse native v1 `Receipt` or T4 sealed `Cut` signatures for this deny-only contract. Proposed bounds: original event at most the existing native 256 KiB request limit; request nonce exactly 32 bytes; page size 1–16 (below native archive's 128); at most 64 pages, 1,024 obligations and 8 MiB total verified response bytes per poll. Overflow is `LIMIT`, never an apparently complete snapshot. A fresh floor expires no later than two seconds after issuance; clock error above 100 ms or an interval crossing the admission epoch is `CLOCK_UNCERTAIN`. The historical acceptance remains durable but must be paired with a **new** floor challenge for each appraisal. Repeated nonce for a different request or signing context is `REPLAY`; identical event/ordinal retransmission returns the same acceptance only after full byte equality. Proposed failure categories are `INVALID_SOURCE`, `UNAUTHORIZED_ISSUER`, `CONFLICT`, `CLOCK_UNCERTAIN`, `FLOOR_STALE`, `PROOF_INCOMPLETE`, `ANCHOR_UNAVAILABLE`, `REPLAY` and `LIMIT`; none falls back to Mesh or 4E-C authority. Values and error encodings are **review candidates**, not approved shared contracts.

The exact native T4 policy context includes the four-witness key roster, quorum/fault bound, epoch length, grants and key-retirement/compromise cut. A revoker grant valid at the full bounded admission interval may support a historical denial after ordinary expiry/rotation; a signed compromise cut overlapping that interval invalidates the admission. A new event under an expired or retired key is rejected. A roster or policy-context transition starts a separately anchored namespace with an explicit consistency/retirement certificate; an agent cannot infer continuity from the same witness name. The agent requires the current enrolled T4 context and T5 policy scope at its final audit commit. Exact transition certificate bytes and adversarial golden vectors are still required from native owners before implementation.

### Ordering and crash recovery

1. A native witness authenticates the original envelope and independently checks the revoker's scoped grant at the **admission epoch**, current compromise/retirement rules, target triple, event ID and publisher sequence. It appends `NativeObligation.v1` to a durable local ledger and advances a protected monotonic local pin before any acceptance response. The first successful durable local append is the **witnessed durable-admission clock start**, even if later anchor work is delayed. Independent harness submission begins when its separate observer records source handoff, not when the agent restarts.
2. The witness sends the exact obligation to the independent anchor through an idempotent outbox keyed by `(T4 context,witness,ordinal,event digest)`. The anchor repeats event/grant checks and durably appends the source bytes, advances its independently protected high-water mark, then signs `NativeAnchorAcceptance.v1`. Only after that authenticated response may the witness persist an anchored state and issue a completed receipt. **There is no cross-host ACID transaction**: this is a write-ahead state machine with retries and no acknowledgement before both durable commits.
3. If killed before local append, there is no witnessed durable admission, but the original submission clock continues. If killed after local append and before anchor commit, the pending obligation remains for replay; no completed receipt or agent-specific denial is claimed. If anchor committed but the witness lost its reply, anchor deduplicates and returns the same accepted record; agents can discover it from the anchor directly. If the anchor cannot prove the latest floor, hold positive authority. A partial anchor write must not return a signed acceptance. Local pin/ledger mismatch disables that witness until independently reconciled; never reset a sequence or issue a fresh lower floor.
4. The enrolled agent directly fetches the anchor's current floor and pages. This is the independent answer to a witness returning a **freshly signed old head**. The agent compares any native witness view with the anchor's per-witness accepted floor. A lower view is stale: use the anchor's authenticated exact source/acceptance proof for the proposed *deny-only* appraisal only if this independent-anchor-equivalent route is separately approved; otherwise `unknown` hold with zero accepted row. A faulty witness cannot hide the source from an honest anchor after completed acceptance, nor invent a valid revoker signature. Anchor staleness, withheld current floor or split view yields `unknown`; a nonce alone never proves latest state.

One anchored acceptance is sufficient **only for local denial of its exact signed target** under the narrow honest-anchor and one-fault-witness assumptions. All required native T5 status operators must supply current complete exact Evidence scope; T5 may remain `reproduced` when Mesh was revoked. Contradiction, expiry, missing view or separate Evidence withdrawal blocks positive authority. A single witness never produces a native 3-of-4 positive cut, authorizes a coordinator hold on arbitrary targets or makes a protected writer transaction valid. If the chosen policy still requires all four fresh witness views, a withholding witness makes a specific accepted row unavailable; retain `unknown` and count the five-second miss. Main/VAL-1 must explicitly choose and test the anchor-equivalent denial rule before any source change.

## Agent-owned audit, identity and migration proposal

`AgentAuditEnrollment.v1` pins operator signature, canonical agent/store UUIDs, resolved DB path, attested host and volume identity, workload credential/key, target roster, executable profile, native T4/T5 contexts and anchor authority. The operator, not Mesh or the coordinator, controls enrollment and credential rotation. A copied SQLite volume/UUID cannot become the scored canonical store. The independent anchor maintains a monotonic per-agent audit high-water `(sequence,root)` outside the agent and target snapshot domains. Startup compares enrolled floor, SQLite hash chain and anchor proof; any rollback, fork or missing external floor blocks positive recovery and does not erase a prior denial.

The proposed profile-2 `BEGIN IMMEDIATE` transaction on the **canonical agent SQLite** commits exactly one `revocation_decisions` row (`revoked_dry_run`/`REVOCATION_ACCEPTED`), exact `revoked_targets` tombstone, matching native T4/T5 and local-map proof provenance, and the next audit-chain hash. Source signed bytes, T4 context/acceptance/current floor, T5 policy/scope/status and both freshness bounds, local inventory/policy/plan snapshot, earliest expiry and bounded clock sample are checked again immediately before commit. Same-ID/different-bytes, target change or `INSERT OR IGNORE` conflict aborts. A separate read-only SQLite connection observes the old table names and new provenance together. Commit-before-anchor may count a durable local denial but positive recovery stays held until the agent audit anchor catches up. Process-local `validated_until_ns` is telemetry, not a restart-proof deadline.

Activation requires an operator-controlled **all-writer barrier**: stop/revoke profile-1 process and old DB/target/broker credentials, fence target-home generation, verify deny-only target state, pin the external audit floor, migrate the existing tables/provenance and start only the enrolled profile-2 executable. A schema marker alone cannot stop an old binary. If an old process can still write the DB or target, cloned hosts share credentials, or the external anchor shares snapshot custody, activation is NO-GO. Legacy decisions are labeled legacy until independently reappraised; no UUID-only upgrade. Preclaim has **zero** target, positive, broker ACK or cursor authority.

## Generation-bound broker and protected-writer contracts — future proposal

`OwnedCursor.v2` would persist `(agent_id,stream kind,broker identity,owner generation,consumer epoch,stream sequence,event digest,decision digest,audit-anchor floor)` under the current enrolled owner. Ordinary and critical cursors have separate monotonic floors. A replayed event can advance a cursor only **after** its agent-owned audit/provenance transaction and a fresh owner-generation check; an ACK follows the durable cursor, with idempotent redelivery after lost ACK. The preclaim denial path advances neither. NATS JetStream does not inspect an application generation attached to `ack_sync()`: an old consumer's physical ACK cannot be called server-fenced merely because application code checked a KV lease. Server-enforced per-generation consumer identity/ACL retirement or a separately reviewed ACK gateway is required; without it, report ACK fencing unproved. A stale ACK cannot substitute for native replay or erase the agent audit/anchor floor.

`ProtectedWriteContext.v2` would bind exact locally signed approval/plan digest and one-use grant, Finding canonical digest, Bundle/claim/material/environment identity, current **native 3-of-4 T4 positive cut**, current two-operator T5 Evidence status, target ID and fence, authenticated workload principal, target-home owner generation, action, and earliest signed/local/lease expiry. The target-owned transaction must recheck all fields, including current Trust freshness and authorization, under the target lock **in the same mutation/audit commit**. A stale signed command, prior-generation holder, expired approval, restored target snapshot or unknown/withdrawn Evidence cannot commit. A restrictive quarantine must remain on incomplete rollback. Current `TargetStore._authorized_write` has some transaction-time checks, but this proposed exact Trust/plan and generation binding is **not claimed as implemented**. Positive ownership transfer and target writes remain outside the deny-only prototype and need a separate cross-component contract review.
