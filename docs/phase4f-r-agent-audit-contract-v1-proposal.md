# Phase 4F-R agent-owned denial contract v1 — proposal

**Review request only; no runtime/source/schema change.** Baseline `d15a3a756b8066c5cb2d98665662220e52f4a7d6`; agent-owned design `67433e52cf8dc8477c1c9a4a93fb5d8cfa133768`; VAL-R conditional prototype review `1b93545` and agent-owned oracle `6c7589e87bcb000f4df0cbe3959d56edea3ea3b3`. External `a51e8a6` target-side denial remains a **separate protective hold**, never an agent decision. This document proposes private, opt-in local interfaces only. Existing signed Mesh and native T4/T5 bytes remain frozen; new encodings need Main and VAL-R approval before implementation. The five-second gate remains failed.

## Trust and scope rule

An agent may enter `unclaimed_deny_only` only as the restarted process of a pre-enrolled deployment, using its operator-pinned canonical SQLite audit store. It cannot connect to NATS, fetch Mesh traffic, ACK, move an ordinary/critical cursor, issue target commands, consume positive approval, emit an allow decision or reopen a route. It directly obtains the complete current native T4/T5 withdrawal view. It verifies the original signed Mesh revocation, issuer grant/scope, local inventory, local denial policy, exact Finding↔Evidence binding and current witnessed status **before** atomically committing its own `revocation_decisions` row, `revoked_targets` tombstone and proof provenance. A generic unknown-status hold is a different record and cannot score as an exact withdrawal denial. Target generation and target-side hold remain independent.

### 1. `AgentEvidenceMap.v1` — exact operator-approved mapping

Canonical body fields (strict, no extras): `kind="aegis.agent-evidence-map.v1"`; `deployment_id` canonical UUIDv4; `agent_id` same enrolled UUIDv4; `audit_store_id` random immutable UUIDv4; `target_id` enrolled local target name; `cohort`, `audience`, `operator_key_id` enrolled names; `finding_id` UUID; `finding_publisher_id` enrolled name; `finding_sha256` lowercase SHA-256 of **existing `artifact.canonical_bytes(Finding)`**, not wire JSON; `finding_sequence` positive integer; `bundle_sha256` lowercase SHA-256 of the canonical native Evidence bundle; `claim_sha256`, `material_scope_sha256`, `environment_sha256` native manifest digests; `inventory_snapshot_sha256`, `policy_snapshot_sha256`, `exact_plan_sha256` local immutable digests; `not_before_ms`, `expires_ms` UTC milliseconds with `not_before_ms < expires_ms`; `nonce` 32-byte hex. Envelope fields: `body`, `signature` base64 Ed25519 over `b"AEGIS-AGENT-EVIDENCE-MAP/v1\x00" + canonical_json(body)`. Canonical JSON is UTF-8, sorted keys, compact separators, no NaN, exact integer types; verification rejects duplicate JSON keys, noncanonical bytes, unknown fields, wrong key role, expired signature or reused nonce. This is a new domain-separated signature **using the existing Ed25519 library**, not a new cryptographic primitive.

The agent first retrieves the exact signed Finding from its locally pinned prior finding/audit record or independently verified T4 history, checks its existing signature and publisher grant, and verifies the stored `finding_sha256`, UUID, publisher and sequence. Mesh `Revocation` v1.1 must match the triple `(target_publisher_id, target_artifact_id, target_sha256)` exactly; v1.0 unbound publisher is **ineligible** for preclaim v1. The Finding must have **exactly one** Evidence reference, and it must pass existing `phase3c.check_bundle`: URI `urn:aegis:evidence:<bundle_sha256>`, matching digest and `lab-reproduction` method. Multiple candidate bundles, URI-only claims or a same-UUID/different-body finding is `unknown`, not an accepted withdrawal. The native bundle's signed Manifest must match `claim_sha256 == digest_bytes(claim_bytes(finding))`, `environment_sha256` and `material_scope_sha256`; the native T5 audience/cohort must equal the map. A native bundle withdrawal **without an exact signed Mesh revocation** can block positive authority and trigger a separate hold but cannot create a Mesh `revocation_decisions` row. Map expiry is one of the earliest deadlines and does not extend a finding or grant.

### 2. `DirectWithdrawalSnapshot.v1` — independently complete discovery

The query is derived from locally enrolled Finding/map digests, not from a coordinator-supplied event ID: `deployment_id`, `agent_id`, `cohort`, `audience`, `finding_sha256`, `bundle_sha256`, locally persisted prior T4 checkpoint root/size and per-witness withdrawal floor, fresh 32-byte challenge nonce, issued-at with clock-error bound, and requested page size ≤256. Send directly to **all four pinned witness endpoints** and both pinned T5 status operators using enrolled workload credentials. Each witness reply contains witness ID/key ID, challenge hash, immutable withdrawal-stream `snapshot_root`, `snapshot_size`, previous-root consistency proof, page `from_position`, contiguous signed leaves/proofs (≤256), `next_position` or terminal marker, signed issued/expiry times and Ed25519 signature. Every page for a witness must bind the same snapshot root/size and nonce; verify dense positions, no duplicates/gaps, inclusion and terminal completeness through `snapshot_size`. Reject missing page, truncated response, conflicting roots, rollback, unsupported algorithm/encoding or size/timeout limit. Discover **all** withdrawals since the locally pinned floor, filter exact target locally, and persist the last complete floor only after appraisal/audit. Current `WithdrawalView` caps `leaves` at 256 and has no reviewed paginated completeness proof; this is a proposed new endpoint/version, not an assumption about current implementation. Ordinary 1,000-row backlog cannot gate this direct read.

All four withdrawal views must be fresh and authenticated. A valid exact scoped withdrawal accepted durably by one pinned witness is denial-precedent only if its signed issuer/grant, receipt and all-view completeness verify. The 3-of-4 sealed T4 history cut is separately required wherever the native positive history policy requires it. T5 must return two independent current status endorsements for the exact claim/bundle/audience and report the specific Mesh withdrawal as `withdrawn`, with contradiction and revocation precedence; two eligible verifier organizations remain required by native policy. An old positive or string reason such as `"mesh-withdrawn"` alone is not this proof. A required view or T5 operator unavailable, stale, equivocal or contradictory yields `unknown/conflict`: block new positive writes and permit only a separately labeled locally authorized hold, **no `revocation_decisions` accepted row**. Recheck every signed/projection deadline after the final network read and immediately before SQLite commit.

### 3. Local snapshot and `VerifiedAgentWithdrawal.v1`

An operator-signed `AgentAuditEnrollment.v1` pins `deployment_id`, `agent_id`, `audit_store_id`, workload principal/credential key pin, canonical path/volume identity, target roster digest, schema profile, initial audit-anchor root/sequence and allowed direct T4/T5 authority key pins. A copied UUID/path is insufficient. The local agent records a signed or hash-pinned `InventoryPolicySnapshot.v1` with immutable snapshot ID, full sorted `(purl, version)` inventory and digest, policy version/digest, exact previously protected finding/plan/target list, local authorization expiry and operator key pin. It re-reads and hashes the full snapshot after the last blocking T4/T5 call and before commit; partial, changed or stale inventory/policy cannot produce a specific accepted denial. The no-broker-lease phase must never rely on coordinator-provided inventory or plan.

`VerifiedAgentWithdrawal.v1` is a **local result**, not a remote authorizing message: `withdrawal_id`, original canonical signed Mesh revocation bytes/digest and key ID; issuer grant digest/role, revocation target triple and sequence; `AgentEvidenceMap.v1` digest; exact T4 witness receipt, complete four-view roots/sizes/floors and consistency proofs/digests; current T5 two-operator status proof digests, exact Evidence scope, contradiction result and earliest expiry; challenge nonce/audience; inventory/policy snapshot IDs/digests; locally bounded clock sample and `validated_until_ns`. An original revocation signed by an expired/revoked key, out-of-scope issuer, invalid sequence or wrong body fails before this result exists. The local result must be revalidated against the pinned source bytes rather than trusted because it serializes consistently. A persisted monotonic deadline is audit telemetry only; after process/host restart a new clock sample and independent appraisal are mandatory.

### 4. Atomic agent-owned SQLite decision

The proposed opt-in audit profile adds `audit_contract_version=2`, immutable `audit_store_id`, and `revocation_provenance_v1(event_id PRIMARY KEY, event_digest, map_digest, signed_wire_sha256, issuer_grant_digest, t4_snapshot_digest, t5_status_digest, inventory_snapshot_sha256, policy_snapshot_sha256, validated_until_ns, audit_anchor_floor, decision_digest)`. The existing `revocation_decisions` and `revoked_targets` tables remain the frozen observation target. Under one `BEGIN IMMEDIATE` transaction on the **enrolled canonical agent database**, check `audit_identity`, store ID, schema profile, local snapshot and post-I/O proof freshness; insert exactly one authenticated `revoked_dry_run` / `REVOCATION_ACCEPTED` row with original publisher, sequence, target triple and digest, one exact `revoked_targets` tombstone, and matching proof provenance. Commit with SQLite durability settings explicitly verified in the disposable fault harness. If the process dies before commit, none of the three rows exists; after commit, all three do. A separately opened read-only SQLite connection, not a worker log or HTTP result, scores the row. Persist only signed public wire and proof digests; credentials, private keys and bearer tokens never enter this table, event payloads or structured logs.

Idempotency key is `(agent_id, withdrawal_id, SHA256(canonical Revocation payload), target_publisher_id, target_artifact_id, target_sha256)`. A same-key replay may return the existing decision **only after comparing every signed byte, target field, proof map digest and local store identity**; differing bytes for the same UUID or reused publisher sequence cause conflict/hold, not `INSERT OR IGNORE`. Two incumbent/replacement processes sharing the canonical database must serialize through SQLite and yield one logical row. A stale agent with a different cloned database cannot produce a scored denial because independent enrollment and audit-anchor checks reject that store. `critical_recovery_cursor` and `recovery_cursor` are neither read as proof nor advanced in this transaction. Later owned replay may advance a generation-bound cursor after it verifies the committed decision/provenance; a broker ACK follows that step and never grants authority.

### 5. Rollback anchor, readers and migration

An `AgentAuditAnchor.v1` is a separate operator-enrolled append-only, independently witnessed high-water mark: `agent_id`, `audit_store_id`, audit sequence, hash of ordered `(event_id, event_digest, target triple, decision_digest, provenance_digest)` rows, previous anchor root/size, checkpoint consistency proof and signer roster. The local SQLite also stores its last accepted root/size. On startup and before any positive recovery, direct independent anchor views must be consistent and at least as high as the local floor; a restored older SQLite snapshot or two divergent copies cause hold and signed-journal reconstitution, never reuse of an old positive decision or silent tombstone deletion. A newly committed negative row may be visible locally before the external anchor is sealed; **positive** authority remains blocked until it is anchored or independently reconciled. If the agent/anchor stores can be rolled back together or the anchor is unreachable, rollback resistance is unproved and the deployment remains held. Local Docker volumes with different keys do not prove independent custody.

Older workers do not understand `audit_contract_version=2`, native proof provenance or preclaim decisions. They must be excluded by an operator-controlled rollout barrier and target-home generation fence **before** the new profile is enabled; merely adding a column is insufficient because current old code ignores unknown tables. An old reader may display a negative row but cannot turn it into current native authority, ACK as a successor or clear it. A new worker reading legacy rows must label them legacy/dry-run, reverify exact signed bytes and native proof before adding provenance, and never silently upgrade a row because its UUID matches. Mixed-version writer, consumer or restored snapshot without the complete barrier stays restrictive and ineligible. Preserve original signed Finding 1.0 and Revocation 1.0/1.1 bytes and publisher ordering for existing readers; preclaim v1 accepts only exact publisher-bound Revocation 1.1. Unsupported new profile fails closed rather than falling back to Mesh-only denial.

## Reader and fault matrix before adoption

| Reader / store | Proposed rule |
| --- | --- |
| Old agent + old store | Continue existing fail-closed Mesh dry-run behavior; no preclaim proof or authority claim. |
| New agent + old store | Read-only migration assessment first. Existing rows remain `legacy` until exact source and native proof are revalidated; do not retroactively count them toward the new five-second test. Operator-enrolled migration writes profile 2 only after all owners/consumers are fenced. |
| Old agent + profile-2 store | **Must be prevented** by operator-controlled executable enrollment, file access and target/consumer generation barrier. Current old `SqliteAudit` ignores unknown tables, so an additive schema alone is unsafe. If the old binary can open/write this store, profile-2 activation is NO-GO. |
| New agent + profile-2 store | Verify enrollment, audit-anchor continuity and local snapshot, then deny-only direct discovery. Normal broker consumption starts only after a valid current owner claim and generation-specific cursor reconciliation. |
| Restored snapshot or cloned UUID/store | If local sequence/root is below the independent anchor or store/host enrollment conflicts, hold positive authority and rebuild from independently witnessed signed history. A clone's row is never counted for the original agent. |

Fault and negative tests: forged/out-of-scope or retired revoker; same UUID/different canonical body; Revocation v1.0 without target publisher; Finding with two Evidence refs or wrong bundle URI; wrong claim/environment/material digest; invalid T5 verifier/operator, contradiction or withdrawn Evidence; one absent or equivocal required withdrawal view; truncated/reordered/paginated page, missing terminal proof, old checkpoint, replayed nonce or expiry after delayed I/O; incomplete/changing local inventory/policy; duplicated local processes and cloned audit store; process death before and after the three-row SQLite commit; lost ACK and stale old-session cursor; restored agent/target/anchor snapshots; coordinator suppression and ordinary-stream saturation. Require no false accepted row, no new positive authority, no target reopening, exact one logical denial on valid replay, and zero cursor/ACK claim from the unclaimed phase.

The frozen release matrix is **72 agent-owned fault pairs plus 18 healthy controls**, with **1,000 ordinary pending findings in every fault run**. Both independently witnessed submission-to-agent-denial and durable-admission-to-agent-denial conservative upper bounds must be ≤5,000 ms for every eligible pair. The test oracle reads each agent's canonical `revocation_decisions` and proof transaction through a separate read-only SQLite connection. Target sentinel hold/fence is measured with a separate target denominator before serving traffic. A crashed/unreachable agent, unavailable required witness view or inaccessible canonical audit store is missed/censored, never replaced by a target proxy or omitted. Report every pair, skip, CPU/RSS and per-stage clock with sound same-host monotonic or bounded cross-host methodology. No physical multi-host, independent witness custody or rollback-anchor deployment evidence exists in this proposal. The current measured five-second gate remains **FAILED / NO-GO**.
