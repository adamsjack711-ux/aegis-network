## Known limits and release posture

The 4F trials were one-host, one-broker, one-database, one dry-run agent; their 30-second values are **dry-run durable audit latency**, not physical target protection time. The retained 5B Linux oracle used a network-disabled container and no syscall tracer. The five-case replication observed filesystem trees through Python, not kernel syscalls. The 5A security case used a scripted provider, not an external model; the independent deterministic holdout had 9/11 mappable exact decisions, two conservative unknown disagreements, and one unmappable Debian epoch case. No provider cost or real-model latency was measured. No independently administered multi-host witnesses, credential custody, external monotonic rollback anchor or complete generation-bound JetStream ACK/cursor barrier has been demonstrated here.

Keep 5A read-only research, 5B CLI alpha, native 4F release, the inherited five-second withdrawal reporting gate, and distributed autonomous enforcement **NO-GO** until their separate frozen acceptance gates pass on reviewed exact integrated commits. Native T4/T5 remains authoritative. Preserve all original failing traces and the Phase 4E startup/key-retirement failure XML. No master merge, production integration, or automatic enforcement is authorized.
