## Reproduced failure and scope

`load_intelligence()` currently calls `trust_path.stat()` to enforce a 1 MiB regular-file limit, then calls `config.load_publishers(path)`, which reopens the pathname and reads it without a bound. The retained test replaces the file after the first check with a JSON grant file over 1 MiB. On this exact baseline, `--runxfail tests/cli_safety_phase5b2/test_grant_race.py` exited 1: **FAILED, DID NOT RAISE ObservationError**. Raw output is `benchmarks/alpha-grant/baseline-grant-race.txt`. The result proves a size/check-use bypass in the observation CLI; it does **not** by itself prove publisher authorization bypass. No network, credential or real host state was used.

The repair scope is the CLI's **local operator-supplied publisher-grant file**. It must parse only the bytes read from one held file descriptor under the 1 MiB cap. A valid publisher signature remains necessary and never proves a vulnerability claim correct. This proposal does not make a path under attacker control into an authenticated trust root: the operator still must enroll and protect the grant file and its path. It does not change the server's or Rapid's authority rules.

## Proposed internal `GrantInputReader.v1` boundary

1. Add **one parser body** in `config.py`: `load_publishers_bytes(raw: bytes) -> TrustStore` strictly decodes UTF-8 and calls the current JSON-to-`PublisherGrant` logic. Keep `load_publishers(path)` as a backward-compatible wrapper around that same parser. The supported Debian/Ubuntu and macOS cells must confirm the existing `Path.read_text()` path loader uses UTF-8 for all golden vectors; if a platform's locale differs, the new CLI byte reader fails closed there until a versioned codec decision. Do not add `publisher_config.py` or copy parser code. Preserve legacy map, grants, roles, scoped revocation, timestamp, revocation and key-rotation interpretation. No canonical signed bytes or grant wire fields change.
2. In the CLI adapter, replace `stat(path) → load_publishers(path)` with `read_local_grants(path, 1_048_576) → load_publishers_bytes(raw)`. The read opens the selected final file **once** and parses only that descriptor's captured bytes. Neither `Path.stat()` nor a second pathname read may authorize content. `load_publishers(path)` stays available to existing callers and delegates to the same parser body; no second grant parser is introduced.
3. **Path root and walk.** Accept absolute paths and relative paths without `..`; resolve a relative path against a single captured `Path.cwd()` before opening. Reject NUL, empty components, `.`, `..` and nonabsolute resolved paths. On Linux, open `/` with `O_RDONLY|O_DIRECTORY|O_CLOEXEC|O_NOFOLLOW`, then open every ancestor through `dir_fd` with those same flags. On macOS only, a literal `/var` or `/tmp` first component may be rewritten to `/private/var` or `/private/tmp` after `lstat` proves that exact symlink is root-owned and resolves to that exact root-owned target; then walk `/private/...` by descriptors. No other symlink is followed. Root and all ancestors must be directories owned by root or the current UID, with no group/other write; a root-owned sticky `01777` directory is an explicit exception for system temporary paths. Same-UID mutation of an operator-controlled path is outside this reader's adversary model; the selected file still gets a single-inode read. If required flags, alias verification or an ancestor check is unavailable or changes, fail closed.
4. **Final open and mode profile.** Open the last component relative to the held parent FD with `O_RDONLY|O_CLOEXEC|O_NOFOLLOW|O_NONBLOCK`; always close parent and file FDs, including error paths. Require `fstat` regular file, owner current UID or root, no group/other write, and mode exactly `0600` or `0644` for Alpha v1. These modes are accepted for both owner classes; root-owned `0600` is practically unreadable to a non-root caller and reports a bounded input error. A root-owned file under an untrusted writable parent is rejected by the ancestor rule. Reject any nontrivial extended ACL on the file or ancestors; Linux must inspect POSIX ACL state on the held descriptor and macOS must inspect its native ACL entries. If ACL presence cannot be established reliably, fail closed for Alpha v1. A filesystem proven by a pinned platform fixture not to support ACLs may report a specific `unsupported` result and be accepted only after independent review. This is a **versioned filesystem-input tightening**: the old content parser accepted other readable modes, so 0640, 0400, 0444 and other forms remain unsupported until explicit compatibility review. Public-key metadata is not a secret; the rule protects integrity, not confidentiality.
5. **Linearization and mutation.** After final `open`, `fstat` once and reject `st_size > 1_048_576`. Read no more than **1,048,577 bytes** from that same FD; reject if the extra byte exists. `fstat` again and require unchanged `(st_dev, st_ino, st_uid, st_gid, st_mode, st_nlink, st_size, st_mtime_ns, st_ctime_ns)` and `len(data) == st_size`. Reject zero-length or incomplete JSON through the parser. A path swap after `open` cannot switch parsed bytes; an observed same-inode rewrite, growth, shrink, permission or owner change fails closed. Metadata checks cannot prove an atomic snapshot against a privileged or same-UID attacker able to manipulate inode metadata; the operator must control file custody, and this one-invocation observation never establishes an independently witnessed latest revocation floor. No retained FD or cache grants later authority.
6. **Error and audit profile.** Missing/oversized, symlinked, nonregular, ACL-unknown, concurrently changed, unreadable, malformed or invalid-key input produces one bounded `ObservationError` and exit 2 in CLI mode. Preserve existing reason distinctions needed by tests, especially the `limit` reason for oversize, without logging grant bytes, public key text, full paths, environment or secrets. No default-state write, optimistic `independent_status`, local approval, Evidence status or protected write can result from parsing this file.

Filesystem controls are **new v1 reader compatibility decisions**, separately measured from unchanged JSON/grant semantics: F00 `0600` and `0644` current-UID/root files; F01 `0666`/`0620` deny; F02 `0640`, `0400`, `0444` deny pending later review; F03 nontrivial ACL or unknown ACL inspection deny; F04 final/ancestor symlink, FIFO/device/socket and `..` deny; F05 path swapped to a different valid key after final `open` still parses **only the opened original inode**; F06 same inode grows beyond 1,048,576 bytes between pre-read `fstat` and read, or metadata changes before post-read `fstat`, deny; F07 1,048,576 bytes inclusive may parse if valid, 1,048,577 denies; F08 current-UID/root-owned safe ancestors and exact macOS aliases allow, group/other-writable non-sticky ancestors deny. Each row records FD `(dev,ino)`, pre/post metadata, selected bytes digest, parser outcome and CLI exit without printing grant bytes.

The existing strict `xfail` test must first be observed failing on the baseline, then pass after the repair without weakening its assertion. Add deterministic descriptor-swap and file-growth negative tests that target the actual new seam, plus no-default-write, local exact match and independent-status-unknown regression. Run focused tests and the full suite on a clean exact integrated commit. VAL must independently rerun the original failure and golden vectors; source-owner green tests alone do not approve intake.

**Test-seam hazard:** the retained xfail monkeypatches `adapter.load_publishers` to replace the file after `stat()`. A repaired adapter may no longer call or even expose that symbol; the old test could then xfail from `AttributeError` or an unrelated expectation while the actual open/read boundary remains untested. Preserve its raw baseline failure, but add a new deterministic hook around the descriptor open/fstat/read sequence. Independently replace the path *after* the descriptor opens and verify the original inode's bounded bytes are parsed, then grow the opened inode during the read and verify denial. A strict xfail count alone is not evidence that the race is fixed. Do not delete the original reproduction.

The successor release oracle must exercise **actual OS-call seams** without a production test bypass: R00 wrap the final `os.open` in the test so that it returns the real FD and then atomically replaces the pathname with a different valid public-key grant before the reader's first `fstat`; authorization must use the original FD/key A, never replacement key B. R01 pause after the first `fstat`, grow the **same opened inode** past 1,048,576 bytes, resume the bounded read, and require a `limit` denial; R02 rewrite the same inode to a different same-size valid key after first `fstat` and require metadata-change denial. R03 inject an error at each open, fstat, read, decode and parser stage and verify all opened FDs close, exit 2 is bounded, and no finding or Evidence status is promoted. R04 run two concurrent readers with a replace between their opens; each result must correspond to the exact inode/bytes it opened, without cross-reader global cache. Retain the original monkeypatch-based xfail and raw failure as historical evidence; only a separately reviewed decision may change its marker after the new real-seam oracle passes. No test is weakened to obtain green output.

## Residual risks and implementation prerequisites

The Alpha reader cannot authenticate who originally created an otherwise valid local grant file, cannot make an attacker-controlled same-UID path safe, and cannot prove that an issuer remains authorized after this one observation. Operator custody, explicit path enrollment and native independent Evidence status are separate controls. Metadata checks detect ordinary same-inode mutation; they do not prove a filesystem snapshot against a privileged actor with metadata control. The supported Debian/Ubuntu and macOS test environments must demonstrate the chosen text codec and ACL-inspection API on real files; an unsupported ACL or no-follow capability is a **skipped/inconclusive platform cell**, not permission to fall back to pathname reading. The old loader's acceptance of alternate modes and duplicate JSON keys is documented compatibility debt, not a reason to loosen the new descriptor boundary without review.
