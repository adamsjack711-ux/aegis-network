## Decision

HOLD for an unrestricted CLI alpha release.** The normal installed launcher now uses an executable POSIX shared script with `exec "${0%/*}/python" -B -P -m aegis.cli "$@"`. The direct PATH smoke trace shows the shell and interpreter `execve` in the **same PID** and no file-write, network, privilege, or child-spawn syscall. It does not change SignedFinding 1.0, exact InventoryItem matching, local authority, grant parsing or enforcement code. The full installed matrix below confirms the behavior. ## Remaining limits and decision scope

The grant reader's benign descriptor walk and `O_NOFOLLOW` path were demonstrated in the original installed matrix, and the revised launcher leaves that code byte-identical. The historical xfail and host same-UID/ACL/mutable-bind custody were not resolved here. The `-B` launcher has been tested through normal absolute/PATH invocation in pinned local Linux images; symlinked invocation outside the venv and direct `sh aegis` without a path were not part of the frozen matrix. The resource metric is child `ru_maxrss`, with cgroup bounds and zero OOM as separate controls; it is not a long-duration host memory guarantee. No real host, production, external model, network feed, or distributed enforcement was tested or authorized.
